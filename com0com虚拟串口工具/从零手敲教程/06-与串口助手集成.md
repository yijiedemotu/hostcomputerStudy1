# 06 · 与串口助手集成（里程碑 M6）

> **本章目标**：让本仓库的串口调试助手在端口下拉框里多出 `VCOM1`/`VCOM2`，选 `VCOM1` 就能和 VComPair 窗口互发，
> 完成"上位机程序 ↔ 虚拟仪表"的完整闭环。
> **验收**：VComPair 点「① 启动服务」→ 串口助手选 `VCOM1` 点「打开串口」→ 两边互发成功。
>
> 本章改的是**仓库主项目**，不是你从零敲的 VComPair 项目。
> 如果你只想要"一个独立工具"，M5 已经完整，本章可以只读原理、不动手。

---

## 1. 为什么这一步几乎不用改业务代码

`Industrial.Core` 里早就抽了一层接口：

```csharp
namespace Industrial.Core.Transport;

public interface ISerialPort : IDisposable
{
    bool IsOpen { get; }
    string PortName { get; }
    void Open();
    void Close();
    void Write(byte[] data);
    int Read(byte[] buffer, int offset, int count, int timeoutMs);
    void DiscardBuffers();
}
```

串口调试助手的接收循环、HEX 解析、定时发送、保存日志，全都只依赖这个接口：

```
MainForm（业务） ──► ISerialPort（抽象） ──┬──► SerialPortNative   物理 COM 口（Win32 API）
                                        └──► VirtualSerialPort   虚拟 VCOM 口（TCP 回环）★本章新增
```

所以本章只做三件事：
1. 新增一个 `ISerialPort` 实现（`VirtualSerialPort.cs`）；
2. 端口列表里加两个名字；
3. 打开串口时按名字选实现。

**接收循环、HEX、定时发送、日志一行都不改** —— 这就是面向接口编程的收益，也是面试里
"没有硬件怎么测串口程序"的标准答案。

## 2. 新增 `VirtualSerialPort.cs`

放在 `项目/src/Industrial.Core/Transport/` 下（和 `ISerialPort.cs`、`SerialPortNative.cs` 同目录）。
`Industrial.Core` 是 `net8.0` 类库，隐式 using 已开，只需显式加两个命名空间。

```csharp
using System.Net.Sockets;
using System.Text;

namespace Industrial.Core.Transport;

/// <summary>
/// 免驱动的虚拟串口客户端（配套工具：com0com虚拟串口工具/VComPair）。
///
/// 【为什么需要它】
/// 真正的虚拟 COM 口（COM5 ↔ COM6）必须由 Windows 内核驱动创建，com0com 就是这样一个驱动，
/// 安装需要管理员权限、且常因驱动签名在 Win10/11 上失败。
/// 本实现走另一条路：用本机 TCP 回环（127.0.0.1:9527）模拟"一根空调制解调器线"，
/// 端点叫 VCOM1 / VCOM2。它同样实现 <see cref="ISerialPort"/>，
/// 所以串口调试助手、Modbus RTU 主站等业务代码一行都不用改，换个实现就能通讯。
///
/// 【和真实串口的差异】
/// * 波特率/数据位/校验/停止位不参与传输（虚拟线没有电气层），但两端参数建议填成一样；
/// * 端口名是 VCOM1 / VCOM2，不会出现在设备管理器里；
/// * 需要一个"服务端"先启动，即 VComPair 工具；第三方只认 COMx 的软件请用真正的 com0com。
///
/// 握手：连接后先发一行 "HELLO|VCOM1|SerialAssistant\n"，服务端回 "+OK|VCOM1\n"；
/// 握手之后的字节全部是串口裸数据，不做分包、不做转义。
/// </summary>
public sealed class VirtualSerialPort : ISerialPort
{
    public const string DefaultHost = "127.0.0.1";
    public const int DefaultPort = 9527;

    /// <summary>可用的虚拟端点，与 VComPair 工具的 VCOM1 / VCOM2 对应。</summary>
    public static readonly string[] VirtualPortNames = ["VCOM1", "VCOM2"];

    private readonly string _portName;
    private readonly string _host;
    private readonly int _port;
    private readonly object _writeLock = new();

    private TcpClient? _client;
    private NetworkStream? _stream;
    private volatile bool _closing;

    public VirtualSerialPort(string portName, string host = DefaultHost, int port = DefaultPort)
    {
        if (!IsVirtualPort(portName))
            throw new ArgumentException(
                $"不是合法的虚拟串口名（应为 {string.Join(" / ", VirtualPortNames)}）：{portName}", nameof(portName));

        _portName = portName.Trim().ToUpperInvariant();
        _host = host;
        _port = port;
    }

    /// <summary>判断一个端口名是不是虚拟端口（大小写不敏感）。</summary>
    public static bool IsVirtualPort(string? name)
    {
        if (name is null) return false;
        var trimmed = name.Trim();
        foreach (var p in VirtualPortNames)
            if (string.Equals(p, trimmed, StringComparison.OrdinalIgnoreCase)) return true;
        return false;
    }

    public string PortName => _portName;

    public bool IsOpen => !_closing && _client?.Connected == true && _stream is not null;

    public void Open()
    {
        if (IsOpen) return;
        _closing = false;

        var client = new TcpClient { NoDelay = true };
        try
        {
            try
            {
                if (!client.ConnectAsync(_host, _port).Wait(1500))
                    throw new IOException($"连接虚拟串口服务超时（{_host}:{_port}）：请先启动『虚拟串口对工具 VComPair』。");
            }
            catch (AggregateException ex)
            {
                throw new IOException(
                    $"连不上虚拟串口服务（{_host}:{_port}）：请先启动『虚拟串口对工具 VComPair』。",
                    ex.InnerException ?? ex);
            }

            var stream = client.GetStream();
            stream.ReadTimeout = 3000;

            var hello = Encoding.UTF8.GetBytes($"HELLO|{_portName}|SerialAssistant\n");
            stream.Write(hello, 0, hello.Length);
            stream.Flush();

            var reply = ReadLine(stream);
            if (!reply.StartsWith("+OK", StringComparison.Ordinal))
            {
                var reason = reply.StartsWith("-ERR|", StringComparison.Ordinal) ? reply[5..] : reply;
                throw new IOException($"虚拟串口 {_portName} 打开失败：{reason}");
            }

            stream.ReadTimeout = Timeout.Infinite;
            _client = client;
            _stream = stream;
        }
        catch (Exception ex) when (ex is not IOException)
        {
            client.Dispose();
            throw new IOException($"连接虚拟串口服务失败（{_host}:{_port}）：{ex.Message}", ex);
        }
        catch
        {
            client.Dispose();
            throw;
        }
    }

    public void Close()
    {
        if (_closing && _client is null) return;
        _closing = true;

        var stream = _stream;
        var client = _client;
        _stream = null;
        _client = null;

        try { stream?.Dispose(); } catch { }
        try { client?.Dispose(); } catch { }
    }

    public void Write(byte[] data)
    {
        var stream = _stream;
        if (!IsOpen || stream is null)
            throw new InvalidOperationException("虚拟串口未打开。");

        try
        {
            lock (_writeLock)
            {
                stream.Write(data, 0, data.Length);
                stream.Flush();
            }
        }
        catch (Exception ex) when (ex is IOException or SocketException or ObjectDisposedException)
        {
            throw new IOException("虚拟串口写入失败：对端工具可能已关闭或连接被断开。", ex);
        }
    }

    /// <summary>
    /// 带超时的阻塞读：用 DataAvailable 轮询而不是 socket 超时异常，
    /// 语义与 <see cref="SerialPortNative.Read"/> 完全一致（超时返回 0，不抛异常）。
    /// </summary>
    public int Read(byte[] buffer, int offset, int count, int timeoutMs)
    {
        var stream = _stream ?? throw new InvalidOperationException("虚拟串口未打开。");
        if (count <= 0) return 0;

        var deadline = Environment.TickCount64 + Math.Max(1, timeoutMs);
        while (true)
        {
            if (_closing || _client is null || !_client.Connected)
                throw new ObjectDisposedException(nameof(VirtualSerialPort));

            if (stream.DataAvailable)
                return stream.Read(buffer, offset, count);

            var remain = deadline - Environment.TickCount64;
            if (remain <= 0) return 0;
            Thread.Sleep((int)Math.Min(10, remain));
        }
    }

    public void DiscardBuffers()
    {
        var stream = _stream;
        if (stream is null) return;
        try
        {
            var tmp = new byte[4096];
            while (stream.DataAvailable) stream.Read(tmp, 0, tmp.Length);
        }
        catch { /* 连接已断开时忽略 */ }
    }

    public void Dispose() => Close();

    /// <summary>读一行 UTF-8 握手响应（握手阶段 stream.ReadTimeout = 3000ms）。</summary>
    private static string ReadLine(NetworkStream stream)
    {
        var bytes = new List<byte>();
        var one = new byte[1];
        while (bytes.Count < 1024)
        {
            var n = stream.Read(one, 0, 1);
            if (n == 0) break;
            if (one[0] == (byte)'\n') break;
            bytes.Add(one[0]);
        }
        while (bytes.Count > 0 && bytes[^1] == (byte)'\r') bytes.RemoveAt(bytes.Count - 1);
        return Encoding.UTF8.GetString(bytes.ToArray()).Trim();
    }
}
```

### 最关键的一段：`Read()` 为什么用 `DataAvailable` 轮询

```csharp
if (stream.DataAvailable) return stream.Read(buffer, offset, count);
...
if (remain <= 0) return 0;      // 超时返回 0，不抛异常
Thread.Sleep((int)Math.Min(10, remain));
```

`ISerialPort.Read` 的**契约**是「最多等 timeoutMs 毫秒，没数据返回 0（不是异常，便于循环）」。
串口助手的接收循环是：

```csharp
while (!_closing && _port is not null)
{
    var n = port.Read(buffer, 0, buffer.Length, 50);
    if (n <= 0) continue;
    ...
}
```

如果这里改成 `stream.ReadTimeout = 50` + 捕获 `IOException`，每次超时都要抛一次异常，
50ms 一轮就是每秒 20 次异常，性能很差，而且不同 .NET 版本抛的内层异常还不一样。
用 `DataAvailable` 轮询（最多睡 10ms）既满足契约，又干净可控。

> **这就是"实现接口时必须遵守语义"**：不是把方法签名凑齐就算实现完了。

### 其它逐段要点

| 片段 | 说明 |
|---|---|
| `VirtualPortNames` | 静态数组，界面列端口和判断端口类型共用，避免两处硬编码不一致 |
| `IsVirtualPort` | 大小写不敏感；写 `vcom1` 也能识别 |
| 构造函数校验 | 传 `COM3` 进来直接抛 `ArgumentException`，防止误用 |
| `Open()` 的中文提示 | 连不上就明说"请先启动 VComPair"，现场排障第一课：错误信息要能指导下一步 |
| `catch (Exception ex) when (ex is not IOException)` | 异常过滤器：把非 IOException（如 SocketException）统一包成带上下文的 IOException |
| `DiscardBuffers()` | 排空 `DataAvailable`，对应 `PurgeComm` 的清缓冲语义 |
| `Dispose() => Close()` | 和 `using` / `port?.Dispose()` 配合，保证连接释放 |

### 改动 2：`RefreshPortList()` 整体替换

```csharp
    private void RefreshPortList()
    {

        var ports = SerialPortNative.GetPortNames();
        cboPort.Items.Clear();

        if (!string.IsNullOrWhiteSpace(current) && !ports.Contains(current))
```

替换后：

```csharp
    /// <summary>
    /// 刷新串口列表。插拔 USB 转串口后点“刷新”就会重新读注册表。
    /// 列表末尾固定追加 VCOM1 / VCOM2 两个免驱动虚拟口（由 VComPair 工具提供），
    /// 这样一台没有串口、也没装 com0com 的电脑也能完整练习收发。
    /// </summary>
    private void RefreshPortList()
    {
        var current = cboPort.Text.Trim();
        var physical = SerialPortNative.GetPortNames();

        var ports = new string[physical.Length + VirtualSerialPort.VirtualPortNames.Length];
        Array.Copy(physical, ports, physical.Length);
        Array.Copy(VirtualSerialPort.VirtualPortNames, 0, ports,
            physical.Length, VirtualSerialPort.VirtualPortNames.Length);

        cboPort.Items.Clear();
        cboPort.Items.AddRange(ports);

        // 保留当前选择/手输的端口；初始为空时默认给一个免驱动虚拟口
        cboPort.Text = string.IsNullOrWhiteSpace(current)
            ? VirtualSerialPort.VirtualPortNames[0]
            : current;

        // 没检测到物理串口时给出提示，并明确告诉用户还有一条免驱动的路
        lblTips.Text = physical.Length == 0
            ? "未检测到物理串口：可选 VCOM1/VCOM2（先启动『虚拟串口对工具 VComPair』），或检查 CH340/CP2102/FT232 驱动"
            : $"检测到 {physical.Length} 个物理串口：{string.Join("、", physical)}；另可用 VCOM1/VCOM2 虚拟串口";
    }
```

## 4. 端到端验收

```powershell
cd D:\上位机\上位机学习大全

# 终端 1：虚拟串口对服务
dotnet run --project com0com虚拟串口工具/VComPair       # 窗口里点「① 启动服务」

dotnet run --project 项目/src/SerialAssistant          # 端口选 VCOM1 → 「打开串口」
```

| # | 动作 | 预期 |
|---|---|---|
| 1 | 串口助手端口下拉框 | 能看到 `VCOM1`、`VCOM2`（物理口之后） |
| 2 | 选 `VCOM1` 点「打开串口」 | 状态变绿，提示"已打开虚拟串口 VCOM1" |
| 3 | VComPair 的 VCOM2 面板输入 `Hello COM!` 点发送 | 串口助手接收区出现 `[时间] Hello COM!` |
| 4 | 串口助手发 `01 03 00 00 00 0A C5 CD`（HEX 发送） | VComPair 的 VCOM2 面板收到 `RX ←`，监控窗口打印 `VCOM1→VCOM2 8B` |
| 5 | 串口助手勾「定时发送」间隔 1000 | VCOM2 每秒收到一帧 |
| 6 | 先关 VComPair 服务再在助手里点发送 | 弹中文错误"虚拟串口写入失败…"，不崩溃 |

## 5. 这一步真正的价值（面试讲法）

| 说法 | 对应的代码 |
|---|---|
| "我把传输层抽象成 `ISerialPort`，业务只依赖接口" | `MainForm` 里 `_port` 是接口类型 |
| "物理串口用 Win32 `CreateFile` 实现，没硬件时用 TCP 回环实现同一个接口" | `SerialPortNative` / `VirtualSerialPort` |
| "换实现时业务代码 0 改动" | 本章只改了字段类型、端口列表、按名分流 |
| "单元测试可以塞内存假串口" | `SelfCheck` 里的 RTU 内存回环就是这个思路 |
| "实现接口要遵守语义，不只是凑齐方法签名" | `Read` 用 `DataAvailable` 保证超时返回 0 |
