## 3. 面试怎么讲这个项目（STAR 版）

**S（情境）**：学习上位机时没有物理串口，com0com 又需要管理员权限和内核驱动签名，公司/笔记本上装不上。

**T（任务）**：做一个零依赖、零管理员权限的虚拟串口对，让串口调试助手能完整收发、联调。

**A（做法）**：
1. 用 `ISerialPort` 抽象传输层，物理口走 Win32 `CreateFile`，虚拟口走本机 TCP 回环，业务代码不改；
2. 服务端 `PairHub` 实现监听、HELLO 握手、端点独占、双向透明转发、离线缓存、回环模式；
3. 客户端 `VirtualClient` / `VirtualSerialPort` 遵守同一握手协议；`Read` 用 `DataAvailable` 轮询保证"超时返回 0"的串口语义；
4. UI 用 Dock + SplitContainer，后台事件一律 `BeginInvoke` 切回 UI 线程；
5. 用 PowerShell 手工客户端 + 布局 Bounds 自检做验证，修掉 6 个真实缺陷。

**R（结果）**：`dotnet build` 0 错误 0 警告；双向收发、超时语义、端口独占、回环、离线缓存、中文标签全部通过；串口助手无需硬件即可联调。

**加分点**：能主动说清**局限** —— VCOM 不是内核设备对象，第三方只认 `COMx` 的软件仍需 com0com；不模拟波特率/握手信号/RTU 3.5 字符间隔；只监听 `127.0.0.1`。

## 5. 和真实 com0com 的边界（别混淆）

| | 本项目 VComPair | com0com |
|---|---|---|
| 层次 | 用户态 .NET 程序 | 内核态驱动 `com0com.sys` |
| 端口 | `VCOM1` / `VCOM2`（逻辑端点） | `COM5` / `COM6`（设备管理器可见） |
| 谁能用 | 已适配的程序 | 任何只认 `COMx` 的软件 |
| 权限 | 普通用户 | 管理员 + 驱动签名 |
| 时序仿真 | 无 | 可开 `EmuBR` / `EmuOverrun` / `EmuNoise` |

需要让第三方软件看到真 COM 口，请读本专题的
[02 安装](../02-com0com下载安装完整教程.md) / [03 创建端口对](../03-创建串口对与命令行详解.md) / [05 排错](../05-故障排查与卸载.md)。
