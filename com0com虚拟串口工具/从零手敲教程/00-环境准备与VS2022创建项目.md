# 00 · 环境准备与 VS 2022 创建项目（里程碑 M0）

> **本章目标**：从一台只有 Windows 的电脑开始，建出一个能 F5 弹出空窗口的 WinForms 项目。
> **验收**：按 F5，出现标题为「VComPair · M0」的窗口，能拖动、能最大化、关掉不报错。

---

## 1. 安装 Visual Studio 2022

1. 下载 [Visual Studio 2022 Community](https://visualstudio.microsoft.com/zh-hans/vs/community/)（免费）。
2. 运行安装程序（Visual Studio Installer），在**工作负载**页勾选：

   ```
   ☑ .NET 桌面开发（.NET desktop development）
   ```

   右侧"安装详细信息"里确认包含：
   - `.NET 8 SDK`（或更高，本教程用 `net8.0`）
   - `Windows 窗体设计器`（Windows Forms Designer）
   - `C# 和 Visual Basic Roslyn 编译器`

3. 点「安装」，等待完成（约 5~15 分钟），重启一次电脑。

> 不想装 VS？只装 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) + VS Code 也行：
> 建一个空文件夹，把本章的 `.csproj` / `Program.cs` / `MainForm.cs` 直接写进去，
> 然后 `dotnet run` 即可。本教程所有代码都不依赖设计器。

---

## 2. 新建项目（VS 向导逐步截图式说明）

1. 打开 VS 2022 → **创建新项目**（Create a new project）。
2. 顶部搜索框输入 `Windows 窗体`，语言筛选选 **C#**，选中模板：

   ```
   Windows 窗体应用   （Windows Forms App）
   注意：不要选 "Windows 窗体应用(.NET Framework)"，也不要选 WPF
   ```

3. 点「下一步」，配置：

   | 字段 | 填什么 |
   |---|---|
   | 项目名称 | `VComPair` |
   | 位置 | 任意，例如 `D:\Learn\VComPairFromScratch` |
   | 解决方案名称 | 保持 `VComPair` |
   | ☑ 将解决方案和项目放在同一目录中 | **建议勾上**，目录更干净 |

4. 点「下一步」，框架选：

   | 字段 | 填什么 |
   |---|---|
   | 框架 | **.NET 8.0 (长期支持)** |
   | 高级 → "使用顶级语句" | **不勾**（我们用传统 `Program.Main`） |

5. 点「创建」。

### 生成后的解决方案资源管理器

```
VComPair（解决方案）
└── VComPair（项目）
    ├── 依赖项
    ├── Form1.cs
    │   └── Form1.Designer.cs      ← 双击 Form1.cs 会打开"窗体设计器"
    ├── Program.cs
    └── VComPair.csproj
```

**VS 默认模板会生成 Designer 拖拽文件，我们这套工具用"纯代码布局"，
所以把 `Form1.cs` 和 `Form1.Designer.cs` 一起删掉**（右键 → 删除）。

> 为什么不用设计器？
> 设计器会把布局拆进 `.Designer.cs` 的 `InitializeComponent()`，并且生成大量字段声明；
> 纯代码布局把界面和逻辑放在同一个 `MainForm.cs`，**跟着教程敲、对照、改都不用来回翻文件**。
> 两者最终生成的控件树完全一样，没有优劣，只是教学上纯代码更直观。

## 3. 项目文件 `VComPair.csproj`

双击项目名（或右键 → 编辑项目文件），把内容**整体替换**为：

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net8.0-windows</TargetFramework>
    <UseWindowsForms>true</UseWindowsForms>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <AssemblyName>VComPair</AssemblyName>
    <RootNamespace>VComPair</RootNamespace>
    <ApplicationHighDpiMode>SystemAware</ApplicationHighDpiMode>
  </PropertyGroup>

</Project>
```

### 逐行解释

| 节点 | 作用 | 不写会怎样 |
|---|---|---|
| `Sdk="Microsoft.NET.Sdk"` | SDK 风格项目文件，自动包含目录下所有 `*.cs` | 老式 `.csproj` 要手动列文件 |
| `OutputType=WinExe` | 生成 **Windows 程序**（不弹黑色控制台窗口） | 默认 `Library` 不能运行；写成 `Exe` 会多一个控制台 |
| `TargetFramework=net8.0-windows` | 目标框架；`-windows` 后缀才能用 WinForms/WPF | 去掉后缀会报"找不到 System.Windows.Forms" |
| `UseWindowsForms=true` | 引入 WinForms 引用 + 隐式 `using System.Windows.Forms` | 找不到 `Form` / `Button` |
| `Nullable=enable` | 开启可空引用类型检查，`string?` 才允许为 null | 少了编译期保护，运行时更容易 NullReference |
| `ImplicitUsings=enable` | 自动 `using System; System.Collections.Generic; System.Threading.Tasks; System.Linq;` 等 | 每个文件都要手写一堆 using |
| `AssemblyName` / `RootNamespace` | 输出 exe 名 / 默认命名空间 | 默认跟项目名一致，写出来是为了明确 |
| `ApplicationHighDpiMode=SystemAware` | 高分屏缩放感知 | 125%/150% 缩放时界面模糊 |

> **注意**：`ImplicitUsings` 不包含 `System.Drawing` 和 `System.Windows.Forms` 的全部类型，
> 所以后面每个用到控件/颜色的文件仍要显式 `using System.Drawing;` `using System.Windows.Forms;`。
> `System.Net.Sockets` 也要显式写。

### 零依赖说明

整个项目**没有 `<PackageReference>`**。TCP 用 `System.Net.Sockets`（BCL 自带），
UI 用 WinForms（框架自带），所以离线工控机也能编译，不需要还原 NuGet 包。

## 4. 入口 `Program.cs`

右键项目 → **添加 → 类**（或 `Shift+Alt+C`），文件名 `Program.cs`，内容：

```csharp
using System.Windows.Forms;

namespace VComPair;

internal static class Program
{
    [STAThread]
    private static void Main()
    {
        ApplicationConfiguration.Initialize();
        Application.Run(new MainForm());
    }
}
```

### 逐行解释

| 代码 | 为什么 |
|---|---|
| `[STAThread]` | WinForms 要求主线程是 **单线程单元(STA)**，否则剪贴板、拖放、文件对话框会异常。**不能省** |
| `ApplicationConfiguration.Initialize()` | .NET 6+ 的新 API，一次性完成：启用视觉样式、设置默认字体、按 `ApplicationHighDpiMode` 配 DPI |
| `Application.Run(new MainForm())` | 创建主窗口并进入 **Windows 消息循环**；这行返回时窗口已关闭，程序结束 |
| `namespace VComPair;` | 文件范围命名空间（C# 10+），注意末尾是分号、没有大括号 |

> VS 模板默认生成的是**顶级语句**版 `Program.cs`（没有 `Main`、没有 `[STAThread]`）。
> 我们用传统写法，是为了明确 `STAThread` 和消息循环这两个知识点。

## 5. 第一个窗口 `MainForm.cs`（v0）

右键项目 → 添加 → 类，`MainForm.cs`，内容：

```csharp
using System.Drawing;
using System.Windows.Forms;

namespace VComPair;

public sealed class MainForm : Form
{
    public MainForm()
    {
        Text = "VComPair · M0";
        Size = new Size(800, 500);
        MinimumSize = new Size(600, 400);
        StartPosition = FormStartPosition.CenterScreen;
        Font = new Font("Microsoft YaHei UI", 9F);
    }
}
```

### 逐行解释

| 代码 | 作用 |
|---|---|
| `: Form` | 继承 `System.Windows.Forms.Form`，就是一个窗口 |
| `Text` | 标题栏文字 |
| `Size` | 窗口**外框**尺寸（含边框标题栏）；客户区会略小 |
| `MinimumSize` | 拖到最小时的尺寸下限，防止控件被挤没 |
| `StartPosition = CenterScreen` | 启动时居中，别每次都跑屏幕左上角 |
| `Font` | 设在**窗体**上，所有子控件默认继承（中文用「Microsoft YaHei UI」不会糊） |

> `sealed` 表示不能被继承，这里的窗口不需要再派生，写上能避免误用。

## 7. 常见报错（M0）

| 报错 | 原因 | 解决 |
|---|---|---|
| `找不到类型或命名空间名 "Form"` | 没写 `using System.Windows.Forms;` 或 csproj 没开 `UseWindowsForms` | 补 using / 检查 csproj |
| `程序不包含适合于入口点的静态 "Main" 方法` | `OutputType` 不是 `WinExe`，或 `Main` 写成了实例方法 | 检查 csproj / `private static void Main()` |
| `特性 "STAThread" 无效` | 加到了类上或写错位置 | 必须加在 `Main` 方法上 |
| `找不到 Form1` | 删了 `Form1.cs` 但别处还引用 | 我们 `Program.cs` 已改成 `new MainForm()` |
| `NETSDK1136 目标平台必须指定 windows` | `TargetFramework` 写成 `net8.0` | 改成 `net8.0-windows` |
| 弹了黑色控制台窗口 | `OutputType` 写成 `Exe` | 改回 `WinExe` |
| 中文显示为方框 | 系统没装雅黑 / 字体名写错 | 改成 `new Font("Microsoft YaHei UI", 9F)` 或 `SystemFonts.DefaultFont` |
