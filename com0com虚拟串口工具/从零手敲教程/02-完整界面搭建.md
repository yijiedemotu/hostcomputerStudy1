## 3. 界面设计上的 7 个决定（都是踩坑换来的）

| 决定 | 原因 |
|---|---|
| 按钮宽度留足（120/100） | 中文按钮写死太窄会被裁掉一两个字，如「① 启动服」「停止服」 |
| 标签用短文本 + `ToolTip` | 窗口缩到最小时选项条宽约 508px，长标签会溢出出现横向滚动条 |
| `_lblHubState` 固定宽 130、短文本 | 启动后文字变长不会把整排控件挤开 |
| `_monitor.WordWrap = true` | 长日志自动换行，而不是在右侧被裁切 |
| `_lblStatus.AutoEllipsis = true` | 窄窗口下长状态文字显示省略号，不换行撑破状态栏 |
| `RichTextBox` 限流 20 万字符 | 长时间跑数不卡死（M4/M5 的 `AppendMonitor` / `AppendLine` 里实现） |
| 顶部/选项条 `AutoScroll=true` + `WrapContents=false` | 极端窄窗口的水平滚动兜底，正常尺寸不触发 |

### 逐段讲解

| 片段 | 说明 |
|---|---|
| `internal sealed class TerminalPanel : GroupBox` | 直接**继承 GroupBox**，自带标题和边框，不用再套容器 |
| `public event Action<string>? Log` | 面板往主窗口上报日志用的事件（M4 会接到监控窗口） |
| `_host` / `_port` + `SetTarget` | 主窗口启动服务时把端口告诉两个终端（M4 用） |
| `bar` 用 `FlowLayoutPanel` | 6 个选项控件自动横排，`Margin` 控制间距 |
| `sendRow` 里 `Fill` + `Right` | 文本框吃掉剩余宽度，发送按钮固定右侧 |
| `_recv.ReadOnly = true` | 接收区只读，防止误编辑日志 |
| `_recv.Font = Consolas` | 等宽字体看 HEX 对齐 |
| `ToolTip` | 短标签的完整说明放悬停提示 |

        _btnClear.Width = 100;
        _btnClear.Height = 28;

        _monitor.AppendText(line + Environment.NewLine);
        if (_monitor.TextLength > 200_000)
        {
            _monitor.Select(0, 100_000);
            _monitor.SelectedText = string.Empty;
        }
        _monitor.SelectionStart = _monitor.TextLength;
        _monitor.ScrollToCaret();

## 7. 逐段讲解（重点）

### 7.1 字段为什么用 `readonly` + `new()`

```csharp
private readonly Button _btnStart = new();
```

控件在字段初始化时就创建好，`BuildUi()` 只负责设属性和挂到树上。
`readonly` 保证不会中途被换成另一个 Button 实例（那样事件订阅会丢）。

### 7.2 `_terminals` 字典

```csharp
private readonly Dictionary<string, TerminalPanel> _terminals = new();
```

后面启停服务时要遍历两个面板（`SetTarget` / `DisconnectClient`）、或精确拿到 VCOM2 面板自动连接，用字典比两个字段更方便扩展成 N 个端点。

### 7.3 `AppendMonitor` 的限流

`RichTextBox` 到几十万字符会明显变卡。这里超过 20 万字符就一次删掉前 10 万，避免每帧都做字符串拼接（那样更慢）。`ScrollToCaret()` 让最新日志始终可见。

### 7.4 为什么界面代码里没有 `InitializeComponent()`

因为我们不用设计器。所有控件都在 `BuildUi()` 里创建 —— 这就是"纯代码布局"。
VS 里双击 `MainForm.cs` 不会出现设计器视图（会提示没有 `InitializeComponent`），这是正常的，不影响运行。
