# 04 · 串口调试助手联调实战

> 假设你已经有一对联通的端口：`VCOM1 ↔ VCOM2`（VComPair）或 `COM5 ↔ COM6`（com0com）。
> 这一篇全是**动手步骤**，做完就能在简历里写"独立完成串口通讯联调"。

---

## 0. 三条路线任选一条

| 场景 | 端口 | 对端是谁 |
|---|---|---|
| A（推荐，零驱动） | `VCOM1` / `VCOM2` | VComPair 工具自带的 VCOM2 终端 |
| B（真 COM 口，双实例） | `COM5` / `COM6` | 第二个串口调试助手实例 |
| C（真 COM 口，模拟仪表） | `COM5` / `COM6` | PowerShell 回显脚本 / 自己写的从站程序 |

路线 A 的 5 分钟步骤在 [README §1](README.md)，这里重点讲 B、C，以及三条路线共通的**验收动作**。

## 1. 路线 A：VComPair（复述关键动作）

```powershell
# 终端 1
dotnet run --project com0com虚拟串口工具/VComPair     # 窗口里点「① 启动服务」
# 终端 2
dotnet run --project 项目/src/SerialAssistant          # 端口选 VCOM1
```

VComPair 的 VCOM2 面板 ↔ 串口助手的 VCOM1，互发即可。
右侧"数据监控"会打印 `[时间] VCOM1 → VCOM2  8B  HEX: 01 03 ... | ASCII: ....`。

## 2. 路线 B：com0com + 两个串口助手实例

### 2.1 准备

按 [03 号教程](03-创建串口对与命令行详解.md) 建好 `COM5 ↔ COM6`，确认：

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()   # 应含 COM5、COM6
```

### 2.2 启动两个实例

开两个终端，都执行：

```powershell
cd D:\上位机\上位机学习大全\项目
dotnet run --project src\SerialAssistant
```

> 两个实例是**两个独立进程**，各自独占一个 COM 口，这正是虚拟串口对的用法。
> 如果第二个窗口启动时端口列表没更新，点各自窗口的「刷新」。

### 2.3 参数与打开

| 实例 | 端口 | 其余参数 |
|---|---|---|
| 甲（当作上位机） | `COM5` | 9600 / 8 / None / 1 |
| 乙（当作仪表） | `COM6` | 9600 / 8 / None / 1 |

两个窗口都点「打开串口」，状态变成"已打开 COMx"。

### 2.4 互发验证

1. 甲窗口发送框默认是 `01 03 00 00 00 0A C5 CD`，「HEX 发送」已勾选 → 点「发送 (Ctrl+Enter)」；
2. 乙窗口接收区应出现 `01 03 00 00 00 0A C5 CD`（勾上「HEX 显示」看得更清楚）；
3. 乙窗口发送框改成 `Hello COM6`（**取消**「HEX 发送」）→ 点发送；
4. 甲窗口接收区应出现 `Hello COM6`；
5. 观察两窗口底部状态栏："发 N 字节 / 收 N 字节"应一一对应。

### 2.5 定时发送

在甲窗口勾「定时发送」，间隔设 `1000` ms → 乙窗口每秒收到一帧。
再去乙窗口勾「时间戳」，能看到每帧间隔约 1000ms —— 这就是排查"设备多久回一帧"的常用手法。

### 2.6 保存日志

乙窗口点「保存日志」→ 存成 `.txt`（UTF-8 带 BOM），可以用记事本/Excel 打开复盘。

## 3. 路线 C：把对端换成"会回包的仪表"

只发不回看不出"请求-应答"逻辑。用下面这段 PowerShell 脚本把 `COM6` 变成一个**自动回显 + 应答的从站**（Windows PowerShell 5.1 自带 `System.IO.Ports`，无需装任何包）。

新建 `echo-slave.ps1`：

```powershell
param([string]$PortName = 'COM6', [int]$Baud = 9600)

$port = [System.IO.Ports.SerialPort]::new(
    $PortName, $Baud,
    [System.IO.Ports.Parity]::None, 8,
    [System.IO.Ports.StopBits]::One)
$port.Encoding = [System.Text.Encoding]::ASCII
$port.ReadTimeout = 200
$port.Open()
Write-Host "从站已启动：$PortName @ $Baud，Ctrl+C 退出"

try {
    while ($true) {
        if ($port.BytesToRead -gt 0) {
            $text = $port.ReadExisting()
            Write-Host ("[{0}] 收到: {1}" -f (Get-Date -Format 'HH:mm:ss.fff'), $text.Trim())
            $port.Write("ACK:" + $text.Trim() + "`r`n")
        }
        Start-Sleep -Milliseconds 30
    }
}
finally {
    $port.Close()
    $port.Dispose()
}
```

运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\echo-slave.ps1 -PortName COM6
```

然后串口助手打开 `COM5`，发送 `PING` → 收到 `ACK:PING`。这就完整模拟了"上位机发命令、仪表回包"。

> COM10 及以上把端口名写成 `\\.\COM10`：
> `[System.IO.Ports.SerialPort]::new('\\.\COM10', ...)`。

### 3.1 模拟 Modbus RTU 从站（进阶）

把应答换成固定帧即可。例如上位机发 `01 03 00 00 00 0A C5 CD`，从站回
`01 03 14 00 64 00 C8 ... <CRC>`。更简单的方式是用 VComPair 的**自动应答**功能：
在 VCOM2 面板把发送框填成应答帧、勾「HEX 发送」+「自动应答」，收到任意帧就自动回这一帧。
详见 [06 号教程 §6](06-VComPair免驱动工具完全教程.md)。

> 想练完整的 Modbus RTU 采集（项目 2），把
> `项目/src/ModbusMonitor/config/appsettings.json` 里第 2 台设备的 `Enabled` 改成 `true`、
> `PortName` 改成你的端口名，另一端跑一个会按功能码应答的从站。
> 仓库自带的 `tools/modbus_slave_sim.py` 是 **TCP** 从站，不直接走串口。

## 4. 通用验收清单（三条路线都适用）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 打开端口 | 状态显示"已打开"，按钮变成"关闭串口" |
| 2 | 单帧 HEX 发送 | 对端收到完全相同的字节序列 |
| 3 | 单帧文本发送 | 对端中文/英文不乱码（UTF-8 两边一致） |
| 4 | 反向发送 | 双向都通 |
| 5 | 字节计数 | 发送 N 字节，对端"收 N 字节" |
| 6 | 时间戳 | 每帧前有 `[HH:mm:ss.fff]`，能看出帧间隔 |
| 7 | 定时发送 | 勾上后按设定周期重复发送，取消后立即停止 |
| 8 | 暂停显示 | 勾上后接收区不刷新但计数继续增长 |
| 9 | GB2312 编码 | 切到 GB2312 能正确显示国产仪表的 GBK 报文 |
| 10 | 保存日志 | 导出的 txt 内容与接收区一致 |
| 11 | 关闭再打开 | 关闭后对端能重新占用端口，无"端口被占用"残留 |
| 12 | 拔线/停服务 | 停止服务后再发送，程序给出中文错误提示且不崩溃 |

## 5. 联调时最容易踩的 8 个坑

1. **两边参数不一致** —— 虽然 com0com 默认不限速，真实硬件上 9600/19200 不一致必然乱码。养成两边填一样的习惯。
2. **同一个 COM 口被两个程序打开** —— 报"端口被占用"。一个口只能一个进程占。
3. **HEX 字符数奇数** —— `01 03 0` 会弹"HEX 字符个数必须是偶数"，写成 `01 03 00`。
4. **误把空格当分隔符又忘了勾 HEX** —— 文本模式会把 `01 03` 原样发成 5 个字符，不是 2 个字节。
5. **中文乱码** —— 两端编码要一致；国产仪表常用 GB2312/GBK，本仓库在 `Program.cs` 里已注册 CodePages。
6. **一个 UTF-8 汉字被拆到两次 Read** —— 界面显示成 `?`。生产代码要用 `Decoder` 保留状态或按帧解码后再显示。
7. **"收到的块"不等于"一帧协议"** —— 接收区按每次 Read 换行，TCP/串口都可能粘包/半包，Modbus RTU 要靠 3.5 字符间隔或长度字段切帧。
8. **接收区无限增长卡死** —— 本仓库超过 40 万字符会截掉前 20 万，自己的项目也要做限流。

## 6. 排错顺序（建议照着走）

```
打不开端口
 ├─ 端口列表里有没有？       → 没有：驱动/Ports 类问题，看 05 号教程
 ├─ 是不是被别的程序占了？   → 关掉旧窗口 / 设备管理器查
 ├─ COM10+ 有没有加 \\.\ ？  → 本仓库已自动加，第三方不一定
 └─ 报"不存在/拒绝访问"？    → 看 02 号教程的签名章节

能打开但收不到
 ├─ 对端也打开了吗？
 ├─ 两端是不是同一对（COM5↔COM6，别开成 COM5↔COM5）？
 ├─ 监控窗口有没有打印流向？  → VComPair 的"数据监控"能一眼定位
 ├─ 是不是勾了"暂停显示"？
 └─ 是不是 EmuOverrun 关着导致数据攒着没吐？→ 05 号教程
```
