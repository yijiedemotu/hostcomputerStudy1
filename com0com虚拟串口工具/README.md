# 虚拟串口工具与 com0com 完全教程

> 目标：让**没有物理串口、也不方便装驱动**的电脑，也能把串口调试助手真正跑通、双向收发数据。
> 本文件夹给出两条路线：本仓库自研的免驱动工具（推荐先走），以及 com0com 内核驱动的完整安装/配置/排错教程。

## 1. 5 分钟上手（路线 A，推荐）

环境：Windows 10/11 + [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。不需要管理员权限，不需要 USB 转串口，不需要 com0com。

```powershell
cd D:\上位机\上位机学习大全

# 终端 1：启动虚拟串口对工具（保持窗口不关）
dotnet run --project com0com虚拟串口工具/VComPair
# 双击 com0com虚拟串口工具/一键启动工具.bat 也可以
```

在工具窗口里点 **「① 启动服务」**，看到 `● 服务运行中 · 127.0.0.1:9527`，且 `VCOM2` 显示"已连接 · 内置终端"。

```powershell
# 终端 2：启动串口调试助手（保持终端 1 不关）
dotnet run --project 项目/src/SerialAssistant
```

在串口助手里：

1. 端口下拉框选 **VCOM1**（列表末尾固定有两个 VCOM 项）；
2. 点 **「打开串口」**，状态变成"已打开 VCOM1"；
3. 切回 VComPair 窗口，在左下 **VCOM2** 面板的发送框输入 `Hello COM!`，点 **「发送」**；
4. 串口助手的接收区立刻出现 `[时间] Hello COM!`；
5. 反过来在串口助手发送框输入 `01 03 00 00 00 0A C5 CD`（默认已填好），点 **「发送 (Ctrl+Enter)」**，VCOM2 面板和右侧"数据监控"都会显示这一帧。

**这就完成了完整的串口通讯闭环。** 右侧监控窗口会打印每一帧的方向、字节数、HEX 和 ASCII。

## 2. 什么时候必须用真正的 com0com

- 你用的**第三方串口调试助手 / 组态软件 / 老 PLC 编程软件**，端口下拉框只列设备管理器里的 `COMx`，不接受自定义名字；
- 你要测的是程序里硬编码的 `CreateFile("\\\\.\\COM5")`，不想改代码；
- 你要验证驱动级行为：波特率仿真、缓冲区溢出、DTR/RTS 握手、Modbus RTU 时序。

## 3. 环境要求

| 项 | 路线 A | 路线 B（com0com） |
|---|---|---|
| 系统 | Windows 10/11（x64） | Windows 7 ~ 11，x86/x64（**无 ARM64 包**） |
| .NET | .NET 8 SDK（含 WindowsDesktop） | .NET Framework 2.0（仅 `setupg.exe` 图形工具需要） |
| 权限 | 普通用户 | **管理员** |
| 网络 | 不需要外网，只监听 `127.0.0.1` | 下载安装包需要外网 |
| 驱动 | 无 | 内核驱动 `com0com.sys` |

## 4. 安全提示（装驱动前一定看）

1. **内核驱动拥有系统最高权限**，只从官方 SourceForge 项目页下载：`https://sourceforge.net/projects/com0com/`。
2. 网上有第三方站点提供"2026 重新签名版 / Windows 11 补丁包"，它们**不是 com0com 官方发布**。如果必须使用，务必核对 SHA-256、确认来源、先在虚拟机里验证，不要直接装到生产或办公电脑上。
3. `bcdedit /set testsigning on`（测试模式）会**降低系统安全性**，部分软件/反作弊会拒绝启动，桌面会出现"测试模式"水印。用完请关掉。
4. 开了 Secure Boot / BitLocker 的机器，改启动设置前先备好 **BitLocker 恢复密钥**。
5. 公司电脑装第三方驱动前先问 IT；路线 A 完全在用户态，通常不需要审批。

## 5. 常见问题速查

| 现象 | 先看 |
|---|---|
| 串口助手打开 VCOM1 报"连不上虚拟串口服务" | [06 号教程 §7](06-VComPair免驱动工具完全教程.md) |
| 9527 端口被占用 | 把工具窗口里的"监听端口"改成 9528 再点启动服务 |
| VCOM1 显示"已被占用" | 同一个端点只能被一个程序打开，先断开旧连接 |
| 设备管理器里看不到 COM5/COM6 | [05 号教程](05-故障排查与卸载.md) |
| Code 52 / 黄色感叹号 | [02 号教程 §5](02-com0com下载安装完整教程.md) |
| 第三方软件不认 VCOM1 | 这是设计如此，改用 com0com（路线 B） |
| 发送后程序卡住不动 | [05 号教程：EmuOverrun / EmuBR](05-故障排查与卸载.md) |

> 结论：**路线 A 解决"我要在本仓库把通讯跑通"；路线 B 解决"我要让任意第三方软件看到一对真 COM 口"。** 两条路互不冲突，可同时存在。
