# 03 · 创建虚拟串口对与 setupc 命令行详解

> 前提：已按 [02 号教程](02-com0com下载安装完整教程.md) 装好驱动，且设备管理器里没有感叹号。
> 所有 `setupc` 操作都要**管理员权限**，推荐用开始菜单的 **com0com → Setup Command Prompt** 快捷方式。

---

## 1. 两种方式

| 方式 | 入口 | 适合 |
|---|---|---|
| 图形 `setupg.exe` | 开始菜单 **com0com → Setup**（需 .NET Framework 2.0/3.5） | 第一次用、只想点几下 |
| 命令行 `setupc.exe` | 开始菜单 **com0com → Setup Command Prompt** | 批量、写脚本、精确改名 |

`setupg.exe` 本质就是 `setupc.exe` 的图形壳，两者改的是同一套配置。

---

## 2. 图形方式（setupg）

1. 右键 **com0com → Setup** → **以管理员身份运行**。
2. 主界面列出已有的端口对。点 **Add Pair** 新建一对，默认得到 `CNCA0` / `CNCB0`。
3. 选中某个端口，在 **Port name** 里填 `COM5`（另一端填 `COM6`）。
4. 如果对面软件只认标准端口，勾选 **"Virtual Port ID" / "use Ports class"** 之类的选项（不同汉化版措辞略有差别），让它注册成真正的 `COM<n>`。
5. 点 **Apply** / 确定，等待驱动重新枚举（可能弹"发现新硬件"）。
6. 设备管理器 → 端口 (COM 和 LPT) 应出现新的 COM5 / COM6。

> 图形工具在部分 Win11 上会因缺 .NET Framework 3.5 打不开。启用方法：
> 控制面板 → 程序 → 启用或关闭 Windows 功能 → 勾选 **.NET Framework 3.5 (包括 .NET 2.0 和 3.0)**。
> 不想装就直接看下一节的命令行方式。

---

## 3. 命令行方式（setupc）—— 推荐

### 3.1 打开

```
开始菜单 → com0com → Setup Command Prompt（右键"以管理员身份运行"）
```

如果快捷方式不在，手动开管理员 cmd 并切到安装目录：

```cmd
cd /d "C:\Program Files\com0com"
:: 或
cd /d "C:\Program Files (x86)\com0com"

dir setupc.exe
```

### 3.2 从零创建一对 COM5 ↔ COM6

```
command> install - -
command> list
        CNCA0 PortName=-
        CNCB0 PortName=-
command> change CNCA0 PortName=COM5
command> change CNCB0 PortName=COM6
command> list
        CNCA0 PortName=COM5
        CNCB0 PortName=COM6
```

解释：

- `install - -`：创建一对新端口，两个 `-` 表示两端都用默认参数；
- 第 n 对端口的内部名是 `CNCAn` / `CNCBn`（第一对就是 `CNCA0`/`CNCB0`）；
- `change <内部名> PortName=COM5`：把端口名改成标准 COM 名；
- `list`：随时查看当前所有端口对及参数。

**选号原则**：先用 `[System.IO.Ports.SerialPort]::GetPortNames()` 或设备管理器看哪些号已被占用，选两个空闲号；别用 COM1~COM4（常被主板/USB 转串口占）；**COM10 及以上**在代码里要用 `\\.\COM10` 前缀打开（见 §6）。

### 3.3 让"只认真 COM 口"的软件也能识别（Ports 类）

有些程序不是按名字打开串口，而是枚举"端口类设备"。只改 `PortName=COM5` 可能仍然看不到，需要把端口注册到 Ports 类：

```
command> change CNCA0 PortName=COM#
command> list
        CNCA0 PortName=COM#,RealPortName=COM3
        CNCB0 PortName=-
command> change CNCA0 RealPortName=COM5
command> change CNCB0 PortName=COM#
command> list
        CNCA0 PortName=COM#,RealPortName=COM5
        CNCB0 PortName=COM#,RealPortName=COM4
command> change CNCB0 RealPortName=COM6
```

`PortName=COM#` 里的 `#` 是"让系统自动挑一个空闲号"的意思；挑完用 `list` 看 `RealPortName`，再用 `change ... RealPortName=COM<n>` 改成你想要的号。

也可以在创建时一步到位（官方 FAQ 的写法）：

```
command> install PortName=COM# -
command> install 0 PortName=COM# -
```

### 3.4 删除端口对

```
command> list                 :: 先确认编号
command> remove 0             :: 删除第 0 对（编号以 list/help 输出为准）
command> list
```

> `remove` 的确切参数格式各版本略有差异，先执行 `help` 或 `help remove` 确认；删之前记下编号，别误删正在用的对。

## 4. setupc 命令速查表

| 命令 | 作用 |
|---|---|
| `help` / `help <命令>` | 帮助 |
| `list` | 列出所有端口对及参数 |
| `install - -` | 新建一对端口（默认 CNCA/CNCB） |
| `install PortName=COM# -` | 新建一对，其中一端注册到 Ports 类 |
| `install <编号> <参数> -` | 指定对编号创建 |
| `change <内部名> <参数>=<值>` | 修改端口参数，多个参数用逗号分隔 |
| `remove <编号>` | 删除第 n 对 |
| `update` | 让驱动重新加载所有端口配置 |
| `uninstall` | 卸载全部端口对与驱动 |
| `--no-update install - -` | 建对但暂不刷新驱动（批量创建时用） |

### `change` 常用参数

| 参数 | 默认 | 作用 | 典型用法 |
|---|---|---|---|
| `PortName` | `-` | 端口名，可设 `COM8`、`COM#` | `change CNCA0 PortName=COM5` |
| `RealPortName` | 自动 | Ports 类实际分配的 COM 号 | `change CNCA0 RealPortName=COM8` |
| `EmuBR` | `no` | **波特率仿真**：按配置的波特率限制传输速度 | `change CNCA0 EmuBR=yes` |
| `EmuOverrun` | `no` | **接收缓冲溢出仿真**：缓冲满就丢旧数据，避免程序卡死 | `change CNCB0 EmuOverrun=yes` |
| `EmuNoise` | `0` | 按概率注入错误字节，测试容错 | `change CNCA0 EmuNoise=0.00001,EmuBR=yes` |
| `AddRTTO` / `AddRITO` | `0` | 读总超时 / 读间隔超时的附加毫秒数 | `change CNCA0 AddRTTO=100,AddRITO=100` |
| `ExclusiveMode` | `no` | 端口被应用打开时才显示（隐藏端口） | `change CNCB0 ExclusiveMode=yes` |
| `PlugInMode` | `no` | 配合 ExclusiveMode：对端打开时才显示本端 | `change CNCA0 PlugInMode=yes` |
| `HiddenMode` | `no` | 完全隐藏端口 | 特殊场景 |

**多个参数一次写完**（逗号分隔）：

```
command> change CNCA0 PortName=COM5,EmuBR=yes,AddRTTO=100,AddRITO=100
command> change CNCB0 PortName=COM6,EmuOverrun=yes
```

### 批量创建（很多对时）

每创建一对都会刷新全部驱动，越到后面越慢。官方建议：

```cmd
cd /d "C:\Program Files\com0com"
FOR /L %%i IN (1,1,20) DO setupc --no-update install - -
setupc install
```

前面 20 次都不刷新，最后一条不带 `--no-update` 的 `install` 统一刷新一次。

## 5. 验证端口对真的通了

### 5.1 最快：两个本仓库串口助手实例

```powershell
cd D:\上位机\上位机学习大全\项目
dotnet run --project src\SerialAssistant
```

再开**第二个终端**跑同样命令，一个选 `COM5`，一个选 `COM6`，都点"打开串口"，随便发一帧，另一端应立刻收到。

> 两端波特率/数据位/校验/停止位**填成一样**（默认不仿真时其实不影响数据，但养成好习惯）。

### 5.2 PowerShell 一行枚举

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()
```

应能看到 `COM5`、`COM6`。

### 5.3 自检脚本（本仓库）

```powershell
cd D:\上位机\上位机学习大全\项目
dotnet run --project tools\SelfCheck
```

它验证 CRC / 字序 / RTU 组帧，与虚拟端口无关但可顺手确认协议层没问题。

## 6. 常见坑

| 坑 | 说明 |
|---|---|
| **COM10 以上打不开** | Win32 `CreateFile("COM10")` 会失败，必须写 `\\.\COM10`。本仓库的 `SerialPortNative.cs` 已自动加前缀；第三方软件不一定会 |
| **端口被占用** | 同一个 COM 口只能被一个程序打开。关掉旧的调试助手/上位机再试 |
| **残留旧数据** | 上次一端没打开时攒的数据，下次连接会一次性冒出来。给接收端开 `EmuOverrun=yes` 可避免 |
| **发送后程序卡死** | 见上：给接收端 `EmuOverrun=yes`、发送端 `EmuBR=yes` |
| **第三方软件看不到端口** | 用 `PortName=COM#` 放进 Ports 类，见 §3.3 |
| **端口名改了但不生效** | 执行 `setupc update` 或重启；设备管理器里刷新 |
| **重复执行 install** | 会不断新建端口对！先 `list` 看看，别把编号搞乱 |
| **中文/空格路径** | `setupc` 对路径不敏感，但安装包解压目录尽量别带中文和空格 |
