# 05 · com0com 故障排查、维护与干净卸载

> 按"症状 → 原因 → 解决"查表即可。表中命令默认在**管理员**的 Setup Command Prompt 里执行。

---

## 1. 症状速查表

| # | 症状 | 最可能的原因 | 解决 |
|---|---|---|---|
| 1 | 设备管理器 com0com 带黄色感叹号，**代码 52** | 驱动是测试签名，被 x64 Windows / Secure Boot 拒绝 | [02 号教程 §5](02-com0com下载安装完整教程.md)：换官方签名包 → 测试模式 → 一次性禁用签名 |
| 2 | **代码 10 / 设备无法启动** | 旧版本残留、SYS/INF 版本不一致、驱动没加载 | 干净卸载重装；执行 `setupc update`；重启 |
| 3 | **代码 31 / 56** | 驱动文件损坏或系统策略冲突 | 重新解压官方 ZIP、换 x64 包、检查 Secure Boot |
| 4 | `setupg.exe` 打不开 / 报 .NET 错误 | 缺 .NET Framework 3.5（含 2.0） | 启用 Windows 功能，或改用 `setupc.exe` |
| 5 | `setupc` 报"拒绝访问" | 不是管理员 | 右键"以管理员身份运行" Setup Command Prompt |
| 6 | 安装时报"找不到 INF" | 直接在 ZIP 压缩包里运行 setup.exe | 完整解压到磁盘目录再运行 |
| 7 | 设备管理器有设备，但软件枚举不到 COM 口 | 默认名 `CNCA0` 不在 Ports 类 | `change CNCA0 PortName=COM#` → `list` → `change ... RealPortName=COM5`，见 [03 §3.3](03-创建串口对与命令行详解.md) |
| 8 | 第三方软件只认 `COMx`，填 `CNCA0` 打不开 | 同上 + 软件写死了 `COM` 前缀 | 改成标准 COM 名；COM10+ 还要 `\\.\COM10` |
| 9 | 打开端口报"端口不存在 / ERROR_FILE_NOT_FOUND" | 代码里没加 `\\.\` 前缀，或名字写错 | `CreateFile("\\\\.\\CNCA0", ...)`；本仓库 `SerialPortNative` 已自动加 |
| 10 | 打开端口报"拒绝访问 / 端口被占用" | 同一 COM 口被另一个进程独占 | 关掉旧调试助手；任务管理器找残留进程；设备管理器禁用再启用 |
| 11 | **发送后程序卡死不动** | `EmuOverrun=no`（默认），对端没打开时驱动一直攒数据 | 给接收端 `change CNCB0 EmuOverrun=yes`，给发送端 `change CNCA0 EmuBR=yes` |
| 12 | 上次发的字节"下次连接才冒出来" | 同上，缓冲未溢出 | 同上；或连接前先 `PurgeComm` 清缓冲 |
| 13 | 改波特率看不出速度变化 | 默认不仿真波特率（两端都是软件） | `change CNCA0 EmuBR=yes`；这是默认行为，不是故障 |
| 14 | 端口改名后不生效 | 驱动没刷新 | `setupc update`，或重启电脑 |
| 15 | 执行了多次 `install`，端口对越来越多 | `install` 每次都新建一对 | `list` 查编号 → `remove <n>` 删多余的对 |
| 16 | 测试模式水印 / 部分软件拒绝启动 | `bcdedit /set testsigning on` 开着 | 用完 `bcdedit /set testsigning off` 并重启 |
| 17 | 装完系统蓝屏 / 不稳定 | 内核驱动与系统不兼容 | 立刻卸载、关测试模式；**改用 [VComPair](06-VComPair免驱动工具完全教程.md)** |
| 18 | 卸载后端口还在（幽灵端口） | 隐藏设备残留 | 设备管理器 → 查看 → 显示隐藏的设备 → 卸载灰色 com0com 设备 |
| 19 | ARM64 / 骁龙 Windows 装不上 | 官方只有 i386 / x64 包 | 没有官方方案，用 VComPair |
| 20 | 公司电脑 IT 策略禁止装驱动 | 策略限制 | 不要试图绕过；用 VComPair（纯用户态） |

## 2. 诊断命令清单

以**管理员**打开 cmd / PowerShell，逐条抄：

```powershell
# ① 系统信息：架构、Secure Boot 状态
msinfo32

# ② 启动配置：测试模式是否开着
bcdedit /enum | Select-String -Pattern "testsigning|loadoptions"

# ③ 当前系统认识的串口
[System.IO.Ports.SerialPort]::GetPortNames()

# ④ PnP 设备与状态
Get-PnpDevice -Class Ports | Select-Object FriendlyName, Status, InstanceId
Get-PnpDevice -Class MultiportSerial | Select-Object FriendlyName, Status

# ⑤ com0com 自己的端口对配置
cd "C:\Program Files\com0com"      # 或 Program Files (x86)
.\setupc.exe list
.\setupc.exe help
```

```cmd
:: ⑥ 端口占用快速判断（把 COM5 换成你的端口）
mode COM5
```

> `mode COM5` 报"设备不存在"多半是名字/Ports 类问题；报"拒绝访问"多半是被占用。

## 3. 一个"能打开但收不到"的标准排查流程

```
                    对端程序也打开了吗？
                    ├─ 否 → 打开对端，再发
                    └─ 是 ↓
        两端是不是"同一对"？（COM5↔COM6，不是 COM5↔COM5）
                    ├─ 否 → 换正确的口
                    └─ 是 ↓
        接收端有没有勾"暂停显示"？发送端有没有真的点"发送"？
                    └─ 都正常 ↓
        用 VComPair 的"数据监控"或第三方抓包看字节有没有出来
                    ├─ 没有 → 发送侧问题（HEX 格式、编码、串口参数）
                    └─ 有   → 接收侧问题（缓冲区、帧解析、显示编码）
```

用 VComPair 时最省事：右侧监控窗口直接打印 `VCOM1 → VCOM2  nB  HEX: ...`，
一眼就能判断"到底是谁没发/谁没接"。

## 4. 参数速查（改完记得 `setupc update` 或重启）

```
:: 常用组合：让行为更接近真实串口
change CNCA0 EmuBR=yes,AddRTTO=100,AddRITO=100
change CNCB0 EmuOverrun=yes

:: 想测试程序容错：注入极低概率的错误字节
change CNCA0 EmuNoise=0.00001,EmuBR=yes,EmuOverrun=yes
change CNCB0 EmuNoise=0.00001,EmuBR=yes,EmuOverrun=yes

:: 隐藏设备侧端口，只给用户侧看
change CNCB0 ExclusiveMode=yes
change CNCA0 PlugInMode=yes

:: 刷新驱动使配置生效
update
```

参数含义见 [03 号教程 §4](03-创建串口对与命令行详解.md)。

## 5. 干净卸载（照顺序做）

### 5.1 关闭所有占用端口的程序

关掉所有串口调试助手、上位机、PLC 编程软件、模拟器。任务管理器里确认没有残留进程。

### 5.2 删除端口对并卸载驱动

方式一（推荐，管理员命令行）：

```cmd
cd /d "C:\Program Files\com0com"
setupc uninstall
```

方式二：控制面板 → 程序和功能 → **Null-modem emulator (com0com)** → 卸载。
静默卸载：`"%ProgramFiles%\com0com\uninstall.exe" /S`。

### 5.3 清残留设备

1. `Win + X` → 设备管理器；
2. 菜单 **查看 → 显示隐藏的设备**；
3. 展开"端口 (COM 和 LPT)"和"多端口串行适配器"；
4. 凡是灰色/带感叹号的 `com0com - ...`，右键 → 卸载设备（勾"删除此设备的驱动程序软件"）；
5. 重启电脑。

### 5.4 关闭测试模式

```cmd
bcdedit /set testsigning off
bcdedit /deletevalue loadoptions
```

重启，确认桌面右下角"测试模式"水印消失、`bcdedit /enum` 里没有 `testsigning Yes`。
如果之前关过 Secure Boot，现在可以回 BIOS 重新启用。

### 5.5 卸载后验证

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()   # 不应再有 COM5/COM6（除非本来就有）
Get-PnpDevice -Class Ports | Select-Object FriendlyName, Status
```

## 6. 决策树：什么时候别再折腾 com0com

```
你的目标是什么？
├─ 只想让本仓库的串口调试助手能收发
│    └─ ► 用 VComPair，5 分钟，不用装驱动（06 号教程）
├─ 要跟第三方软件联调，且那软件只认 COMx
│    └─ ► 必须 com0com（或商业虚拟串口驱动）
├─ 公司电脑 / Secure Boot 锁死 / 无管理员权限
│    └─ ► VComPair（纯用户态，监听 127.0.0.1）
├─ 要测真实波特率时序、握手信号、Modbus RTU 3.5 字符间隔
│    └─ ► 真实硬件最准；com0com 只能近似（EmuBR/EmuOverrun）
└─ 只是要跑 Modbus 采集/看板（项目 2 / 项目 3）
     └─ ► 用 Python TCP 模拟器，根本不需要串口
```

> 记住：**com0com 解决的是"端口名/内核设备"的问题，不是"通讯逻辑"的问题。**
> 学习阶段的绝大多数联调，用户态的虚拟线就够了。
