# 15 求职：简历、面试与职业路线

> 本章目标：把你会的东西“卖”出去。技术再好，不会表达也会被低估。
> 配套：附录 C 有 100 道面试题速答。

---

## 1. 先搞清楚岗位要什么

上位机岗位的面试通常考察四块：

| 块 | 权重 | 面试官想确认 |
|---|---|---|
| C# / 桌面开发 | 30% | 你能不能独立写界面和业务 |
| 通信协议 | 30% | 你能不能在现场把设备调通 |
| 数据库 / 数据处理 | 15% | 历史、报警、报表会不会 |
| 工程素养 / 现场 | 25% | 能不能交付、能不能出差、会不会沟通 |

**通信协议是分水岭。** 只会拖控件的人 8k，能独立调 Modbus/S7 的人 15k 起。

## 2. 简历：两页以内

### 2.1 结构

```
姓名 | 电话 | 邮箱 | 城市 | 求职意向
------------------------------------
个人优势（3 行，量化）
专业技能（分类列，别写“精通”）
项目经历（2~3 个，STAR）
工作/教育经历
证书（可选）
```

### 2.2 个人优势示例

> 3 年 C# 上位机开发，独立负责过 6 条产线的上位机从 0 到交付；手写 Modbus RTU/TCP 协议栈，支持 20+ 设备并发采集；主导过一次架构重构，新设备接入周期从 5 天降到 0.5 天；能适应出差与现场调试。

### 2.3 项目描述模板

```
项目名称：XX 产线数据采集与监控系统
角色：上位机负责人（1 人）
技术：C# / .NET 8 / WinForms / Modbus TCP+RTU / SQLite / CSV
职责与成果：
  · 设计分层架构（UI/服务/协议/存储），新增设备只需改 JSON 配置
  · 手写 Modbus 主站（CRC、MBAP、异常码、超时重连），替代第三方库
  · 实现地址合并批量读，20 个点位从 20 帧/周期降到 2 帧，485 总线负载下降 90%
  · 通信故障时上报 Bad 质量并自动重连，界面不再显示过期数据
  · 历史数据按天落盘，支持 3 个月数据查询与班报导出
  · 现场调试 2 周内完成 6 台设备联调，连续运行 30 天无崩溃
```

**量化！** “优化了性能”没人信，“20 帧降到 2 帧”才有说服力。

### 2.4 不要写这些

- “精通 C#”（面试官会往死里问）
- “熟悉 Office”（与岗位无关）
- 只列技术名词，没有场景
- 项目描述全是“负责开发”，没有难点和结果

| 渠道 | 特点 |
|---|---|
| BOSS 直聘 | 上位机岗位最多，可直接聊 |
| 智联/前程无忧 | 传统制造业多 |

## 4. 面试流程与准备

```
HR 电话（5~10 分钟）→ 技术一面（1 小时）→ 技术二面/主管（1 小时）→ HR 谈薪 → offer
```

### 4.1 自我介绍（1 分钟模板）

> 面试官好，我叫 XX，做 C# 上位机开发 3 年。主要做非标设备的数据采集和监控软件，熟悉的协议有 Modbus RTU/TCP、西门子 S7，桌面端用 WinForms 和 WPF。
> 最近一个项目是 XX 产线的中控系统，我负责从架构到现场联调：12 台设备、3 种协议，采集 200 多个点位，历史数据存 SQLite，对接了 MES。
> 我比较擅长现场问题定位，比如有一次 485 总线偶发掉线，最后查到是变频器干扰 + 屏蔽层两端接地，处理后连续运行 7 天没问题。
> 想找一个能长期做、能接触完整项目的上位机岗位。

结构：**我是谁 → 做什么 → 一个亮点 → 为什么来**。

### 4.2 技术面常见节奏

1. 先问项目（占 50%）：架构、难点、你负责什么。
2. 再问基础（占 30%）：C#、线程、协议。
3. 最后场景题（占 20%）：现场连不上怎么办、数据量大怎么办。

**项目讲不清楚，基本就挂了。** 所以第 14 章的答辩 10 问必须练熟。

## 5. 高频面试题（含答案要点）

### 5.1 C# / 语言

**Q1：值类型和引用类型的区别？**
要点：存储位置（栈/堆）、赋值行为（复制值/复制引用）、装箱拆箱、`struct` vs `class`。

**Q2：`string` 为什么不可变？**
要点：不可变保证线程安全和哈希稳定；拼接产生新对象，循环用 `StringBuilder`。

**Q3：`==` 和 `Equals` 的区别？**
要点：`==` 可重载（值比较/引用比较），`Equals` 是虚方法；`string` 重载了 `==` 做值比较。

**Q4：接口和抽象类的区别？**
要点：多实现 vs 单继承；接口定义契约，抽象类可含实现和状态；上位机里 `IModbusMaster` 用接口。

**Q5：`ref` 和 `out` 的区别？**
要点：`ref` 进出都要初始化，`out` 必须在方法内赋值；`TryParse` 用 `out`。

**Q6：委托和事件的区别？**
要点：事件是委托的封装，外部只能 `+=`/`-=`，不能直接调用；发布订阅解耦。

**Q7：`async/await` 原理？**
要点：状态机、`Task`、`SynchronizationContext`；`await` 后回到原上下文（除非 `ConfigureAwait(false)`）。

**Q8：`.Result` 为什么会死锁？**
要点：UI 线程阻塞等任务，任务 `await` 后要回 UI 线程 → 互相等待。

**Q9：`using` 的作用？**
要点：编译成 `try/finally`，调用 `Dispose`；用于释放非托管资源/连接。

**Q10：`IEnumerable` 和 `List` 的区别？**
要点：延迟执行 vs 立即物化；`IEnumerable` 可多次枚举有副作用。

### 5.2 WinForms / WPF

**Q11：跨线程更新界面怎么做？**
要点：`Invoke`（同步）/`BeginInvoke`（异步）、`SynchronizationContext`、`async/await`；采集线程必须用 `BeginInvoke`。

**Q12：界面卡顿怎么排查？**
要点：调试暂停看 UI 线程堆栈；是否同步 IO/`Thread.Sleep`/大量计算；改异步。

**Q13：DataGridView 数据量大怎么优化？**
要点：`VirtualMode`、关闭自动列宽、双缓冲、分页。

**Q14：WPF 绑定不刷新怎么办？**
要点：属性要实现 `INotifyPropertyChanged`、`Mode=TwoWay`、`UpdateSourceTrigger`。

**Q15：MVVM 的优缺点？**
要点：解耦、可测试；学习成本、简单界面过度设计。

**Q16：`DataTemplate` 和 `ControlTemplate` 的区别？**
要点：DataTemplate 描述“数据长什么样”，ControlTemplate 描述“控件长什么样”。

### 5.3 通信 / 协议

**Q17：Modbus RTU 和 TCP 的区别？**
要点：物理层、帧格式（CRC vs MBAP）、端口（串口 vs 502）、分帧方式。

**Q18：Modbus 功能码 03 和 04 的区别？**
要点：03 读保持寄存器（可写），04 读输入寄存器（只读）。

**Q19：40001 对应协议地址是多少？**
要点：0（40001 - 40001）；注意有些设备 1 基址。

**Q20：CRC16 怎么算？**
要点：初值 0xFFFF、多项式 0xA001、低字节先发；能手写代码。

**Q21：ABCD/CDAB 是什么？**
要点：32 位数据在两个寄存器里的字序；错了数值离谱；现场四种都试。

**Q22：粘包/半包怎么处理？**
要点：缓冲区 + 循环解析；按帧头/长度/分隔符/静默时间切帧。

**Q23：TCP 为什么需要心跳？**
要点：中间设备会断空闲连接；应用层保活；心跳失败触发重连。

**Q24：断线重连怎么做？**
要点：捕获异常 → 退避重连 → 重新初始化 → 状态上报；别死循环狂连。

**Q25：RS485 为什么加终端电阻？**
要点：阻抗匹配、减少反射；两端各 120Ω；短距离可省。

**Q26：异常码 02 是什么意思？**
要点：非法数据地址；地址越界/基址错/数量超限。

**Q27：S7 协议端口？和 Modbus 区别？**
要点：102、ISO-on-TCP；直接读 DB/M/I/Q；需关“优化的块访问”。

**Q28：OPC UA 的优势？**
要点：自描述、订阅、安全、跨平台；Endpoint/NodeId/Session。

### 5.4 数据库 / 多线程

**Q29：历史数据表怎么设计？**
要点：TagId、Ts、Value、Quality；索引 `(TagId, Ts)`；按天分区/清理。

**Q30：10 万条数据怎么快速入库？**
要点：事务 + 参数化 + 批量；`SqlBulkCopy`；关自动提交。

**Q31：`lock` 锁什么？**
要点：锁引用类型对象，别锁 `this`/字符串/值类型；锁范围尽量小。

**Q32：`ConcurrentQueue` 和 `Queue` 区别？**
要点：线程安全；生产者消费者。

**Q33：如何优雅退出采集线程？**
要点：`CancellationToken` + `Task.WhenAll` + 超时 + 刷盘。

**Q34：采集周期 500ms，20 个点位，怎么保证不超时？**
要点：批量读、算帧耗时、降低周期或分设备。

### 5.5 工程 / 现场

**Q35：现场连不上设备，你怎么排查？**
要点：物理层→参数→站号/地址→协议→程序；用串口助手/抓包；讲一个真实案例。

**Q36：程序在现场跑几天内存涨，怎么办？**
要点：事件未退订、集合无限增长、GDI 对象、日志队列；用任务管理器/诊断工具。

**Q37：怎么保证断电不丢数据？**
要点：事务/WAL、及时 flush、UPS、备份、断点续传。

**Q38：客户临时加需求怎么办？**
要点：确认范围、评估工期、走变更单、留书面记录。

**Q39：你如何做版本升级？**
要点：版本号、配置兼容、数据库迁移、回滚、灰度。

**Q40：为什么选择上位机这个方向？**
要点：喜欢“软件 + 现场”的结合，能看到实物动起来；愿意出差；长期做工业软件。

## 6. 手写代码题（白板/共享屏幕）

1. 反转字符串 / 判断回文。
2. 冒泡/快速排序。
3. 单例（懒汉 + 双重检查 + `volatile`）。
4. 手写 CRC16。
5. 手写 `TryParseHex`。
6. 两个线程交替打印 1~100。
7. 生产者消费者（`BlockingCollection`）。
8. 统计字符串里每个字符出现次数。
9. 单链表反转。
10. 找出数组中和为 target 的两个数。

> 上位机岗位的手写题不难，**但 CRC 和线程题一定要会**。

## 7. 反问面试官（体现专业度）

- 团队现在做的是标准机还是非标线？出差比例多少？
- 上位机是自研框架还是每个项目复制一套？
- 通信协议主要有哪些？有没有用到 OPC UA？
- 项目周期一般多久？现场调试由谁负责？
- 代码有 review 和版本管理吗？
- 这个岗位未来一年最重要的目标是什么？

## 8. 薪资谈判

1. 先问范围：“这个岗位的预算区间大概是多少？”
2. 报期望时给区间，且下限是你的底线。
3. 用事实支撑：项目难度、独立交付能力、现场经验。
4. 关注总包：基本工资、绩效、出差补贴、年终、加班情况。
5. 不要编造当前薪资（背调会查）。

## 9. 入职前 90 天

| 阶段 | 目标 |
|---|---|
| 第 1~2 周 | 装环境、跑通现有项目、读代码、看文档 |
| 第 3~4 周 | 接手一个小模块（改界面/加点位/修 bug） |
| 第 2 个月 | 独立负责一台设备/一个页面，参与现场调试 |
| 第 3 个月 | 能独立处理常见现场问题，输出一份文档 |

**前 30 天多问、多记、少改。** 把“这个项目为什么这么设计”搞清楚，比急着表现更重要。

## 10. 职业路线

```
0~2 年：能独立完成单设备/单工位上上位机
2~5 年：能负责整线、多协议、MES 对接、带 1~2 人
5 年+：SCADA/架构/项目经理/技术专家
       ↘ 视觉（Halcon/OpenCV）
       ↘ 运动控制（C++/Qt/固件）
       ↘ 产品/售前（懂工艺 + 懂软件）
```

长期建议：

1. **深耕一个行业工艺**（锂电、光伏、汽车零部件、包装、注塑）。
2. **补上数据库和网络**，往 SCADA/MES 走。
3. **学一点前端**（Vue/React），做 Web 看板很吃香。
4. **保持写文档和复盘**，这是从“干活”到“负责”的分界线。
