## 1. 项目 0：协议自检工具 SelfCheck

### 1.1 它解决什么问题

写协议最怕“看起来能跑，其实解析错了”。SelfCheck 用**已知报文 + 内存回环从站**验证：

1. CRC16 是否等于标准值（`01 03 00 00 00 0A → CDC5`）；
2. 四种字序编解码是否往返一致；
3. RTU 组帧、CRC 校验、超时是否正常（不用真串口）；
4. TCP 联调（需要模拟器）：读、写、异常码；
5. 采集引擎：3 秒内是否收到快照、故障时是否上报 Bad。

### 1.2 运行

```powershell
cd 项目
dotnet run --project tools/SelfCheck            # 离线部分
python tools/modbus_slave_sim.py                # 另一个终端
dotnet run --project tools/SelfCheck -- 502     # 含联调
```

预期输出：全部 ✔，退出码 0。

### 1.3 关键代码

| 文件 | 内容 |
|---|---|
| `tools/SelfCheck/Program.cs` | CRC/字序/RTU/TCP 测试；`LoopbackRtuSlave` 假串口 |
| `tools/SelfCheck/PollingTests.cs` | 采集引擎端到端 + 故障降级 |

`LoopbackRtuSlave` 是重点：它实现 `ISerialPort`，把“写出去”的请求解析后生成应答塞回接收队列。
**一个假串口就验证了主站的全部逻辑**——这就是接口抽象的价值。

### 1.4 扩展

- 增加 0x01/0x02/0x0F 的测试；
- 增加故意错误 CRC 的用例，验证主站报错；
- 用 xUnit 重写，接入 CI。

### 2.3 关键流程

**打开串口**：

```csharp
var settings = new SerialSettings { PortName = "COM3", BaudRate = 9600 };
var port = new SerialPortNative(settings);
try { port.Open(); }
catch (Exception ex) { ShowError("打开串口失败", ex); return; }
```

`SerialPortNative` 把 Win32 错误码翻译成中文（端口不存在/被占用/参数非法）。

**接收**：后台 Task 循环读，`BeginInvoke` 回 UI：

```csharp
var n = port.Read(buffer, 0, buffer.Length, 50);
if (n > 0) BeginInvoke(new Action<byte[]>(AppendReceived), chunk);
```

**发送**：HEX 解析要容忍空格、逗号、`0x` 前缀，字符数必须偶数：

```csharp
internal static byte[] ParseHex(string text)
{
    // 过滤 0x、空格、逗号；校验非法字符与奇数长度
}
```

**定时发送**：`System.Windows.Forms.Timer`，注意开关状态与串口状态联动。

| 文件 | 内容 |

### 2.5 常见坑（这个项目踩一遍，面试就不怕问）

1. **文本解码跨包**：一个 UTF-8 汉字 3 字节，可能被拆到两次 Read 里，显示成乱码。
   → 生产项目要用 `Decoder` 保存状态，或按帧解析完再解码。
2. **接收区无限增长**：RichTextBox 到几百万字符会卡死。
   → 本仓库超过 40 万字符就截掉前一半。
3. **关闭串口时接收线程还在读**：会抛 `ObjectDisposedException`/`IOException`，必须捕获并退出。
4. **HEX 显示每帧换行**：实际收到的“块”不等于协议“帧”，要看帧得自己解析。
5. **GB2312 需要注册 CodePages**：.NET Core 默认不带。

### 3.3 采集流程（重点）

```csharp
// 1. 分组：相邻地址合并，≤125 个寄存器
var groups = BuildGroups(device);

// 2. 逐组读
foreach (var group in groups)
{
    var registers = await master.ReadHoldingRegistersAsync(
        device.SlaveId, group.Start, (ushort)group.Count, ct);

    // 3. 每个点位从组内偏移解码
    foreach (var point in group.Points)
        values.Add(Decode(device, point, registers, group.Start));
}

// 4. 抛快照（后台线程）
RaiseSnapshot(values);
```

解码：

```csharp
var raw = RegisterCodec.Decode(regs.AsSpan(offset, count), point.DataType, point.Order);
var engineering = RegisterCodec.ToEngineering(raw, point.Scale, point.Offset);
var alarm = engineering > high ? AlarmLevel.High : engineering < low ? AlarmLevel.Low : AlarmLevel.None;
```

## 5. 二次开发：换成你的设备

以项目 2 为例，接一台真 PLC：

1. 改 `config/appsettings.json`：`Host/Port/SlaveId/Points`；
2. 若走 485：把设备改成 `"Protocol": "ModbusRtu"`，填 `PortName/BaudRate/Parity`；
3. 按 PLC 手册填 `Address`（注意 40001 ↔ 0）、`DataType`、`Scale`、`Order`；
4. 启动程序，看日志里的原始寄存器值；
5. 用 SelfCheck 或串口助手交叉验证；
6. 调报警限、量程、单位。

> 接新协议（S7/OPC UA）：实现 `IDeviceDriver` 或扩展 `IModbusMaster` 工厂，采集服务不用改。
