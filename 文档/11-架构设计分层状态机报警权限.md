## 1. 典型上位机架构

```
┌─────────────────────────────────────────────┐
│  UI 层（WinForms / WPF）                     │
│  主界面 / 参数页 / 报警页 / 报表 / 登录       │
└──────────────────┬──────────────────────────┘
                   │ 事件 / 命令 / 绑定
┌──────────────────▼──────────────────────────┐
│  应用层（Services）                          │
│  采集服务 / 报警服务 / 配方服务 / 权限服务     │
└──────────────────┬──────────────────────────┘
                   │ 接口调用
┌──────────────────▼──────────────────────────┐
│  领域层（Models + 规则）                     │
│  AppConfig / TagValue / 报警判定 / 状态机     │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  基础设施层（Infrastructure）                │
│  Modbus / S7 / OPC UA / 串口 / 数据库 / 日志  │
└─────────────────────────────────────────────┘
```

依赖只能从上往下。**UI 里出现 `TcpClient` 就是分层失败。**

## 2. 设备驱动：一个接口适配所有协议

```csharp
public interface IDeviceDriver : IDisposable
{
    string Name { get; }
    bool IsConnected { get; }
    Task ConnectAsync(CancellationToken ct);
    Task<IReadOnlyList<TagValue>> ReadAsync(CancellationToken ct);
    Task WriteAsync(string tagName, double value, CancellationToken ct);
}
```

实现：

```csharp
public sealed class ModbusDeviceDriver : IDeviceDriver { ... }
public sealed class S7DeviceDriver : IDeviceDriver { ... }
public sealed class OpcUaDeviceDriver : IDeviceDriver { ... }
```

工厂按配置创建：

```csharp
public static IDeviceDriver Create(DeviceConfig config) => config.Protocol switch
{
    DeviceProtocol.ModbusTcp => new ModbusDeviceDriver(config),
    DeviceProtocol.ModbusRtu => new ModbusDeviceDriver(config),
    DeviceProtocol.S7 => new S7DeviceDriver(config),
    _ => throw new NotSupportedException()
};
```

好处：**加一个新协议 = 加一个类，不改采集服务、不改界面。**

## 3. 设备状态机

不要用一堆 bool 表示状态，用枚举 + 明确迁移：

```csharp
public enum DeviceState
{
    Offline,       // 离线
    Connecting,    // 连接中
    Online,        // 在线空闲
    Running,       // 运行中
    Alarm,         // 报警
    Fault          // 故障
}
```

允许的迁移：

```
Offline → Connecting → Online → Running ⇄ Alarm
                ↓          ↓        ↓
              Fault ←──────┴────────┘
```

代码里集中判断：

```csharp
public bool CanStart => State is DeviceState.Online or DeviceState.Alarm;
public bool CanReset => State is DeviceState.Alarm or DeviceState.Fault;
```

**好处**：界面按钮的可用状态、联锁逻辑、日志都能统一，不会出现“既运行又离线”的鬼状态。

## 4. 报警设计（比想象的复杂）

### 4.1 报警级别

| 级别 | 含义 | 处理 |
|---|---|---|
| 提示 Info | 一般信息 | 记录 |
| 警告 Warning | 接近限值 | 黄色、记录 |
| 报警 Alarm | 超限 | 红色、声光、记录 |
| 故障 Fault | 通信/设备故障 | 红色闪烁、停机联锁 |

### 4.2 五个必须考虑的问题

1. **死区（Deadband）**：950 触发，945 恢复，避免在阈值附近反复报警。
2. **延时确认**：连续 3 个周期超限才报，滤掉毛刺。
3. **状态翻转记录**：只在“正常→报警”“报警→正常”时各记一条，不是每周期都记。
4. **确认与复位**：操作工点“确认”只表示知道了，故障消失才恢复。
5. **报警抑制**：设备停机时屏蔽相关工艺报警，避免刷屏。

```csharp
public sealed class AlarmEvaluator
{
    private readonly Dictionary<string, AlarmLevel> _state = new();
    private readonly Dictionary<string, int> _counters = new();

    public AlarmLevel Evaluate(string key, double value, PointConfig p, int confirmCycles = 3)
    {
        var level = value > (p.HighLimit ?? double.MaxValue) ? AlarmLevel.High
                  : value < (p.LowLimit ?? double.MinValue) ? AlarmLevel.Low
                  : AlarmLevel.None;

        var previous = _state.GetValueOrDefault(key, AlarmLevel.None);
        if (level == previous) { _counters[key] = 0; return previous; }

        _counters[key] = _counters.GetValueOrDefault(key) + 1;
        if (_counters[key] < confirmCycles) return previous;

        _state[key] = level;
        _counters[key] = 0;
        return level;   // 调用方据此写报警表
    }
}
```

### 4.3 报警记录字段

时间、位号、级别、触发值、限值、确认人、确认时间、恢复时间、备注。
验收时客户一定会问“这条报警谁确认的”。

## 5. 配方（Recipe）

场景：同一台设备要生产 10 种产品，每种产品的温度、压力、时间不同。

```csharp
public sealed class Recipe
{
    public string Name { get; set; } = "";
    public int Version { get; set; } = 1;
    public DateTime UpdatedAt { get; set; }
    public Dictionary<string, double> Parameters { get; set; } = new();
}
```

流程：

```
选择配方 → 校验参数范围 → 下发到 PLC → 读回校验 → 记录审计
```

注意：

- 下发失败要能回滚/重试；
- 配方要有版本和修改人；
- 生产中的配方不允许随便改（加锁）；
- 参数要有上下限校验，别把 500℃ 写进 200℃ 的设备。

## 6. 权限与审计

### 6.1 角色

| 角色 | 权限 |
|---|---|
| 操作员 Operator | 查看、启停、确认报警 |
| 工程师 Engineer | 改参数、配方、标定 |
| 管理员 Admin | 用户管理、系统设置 |

### 6.2 实现要点

```csharp
public enum Permission { View, Operate, EditParameter, ManageUser }

public bool HasPermission(User user, Permission permission) =>
    user.Role switch
    {
        "Admin" => true,
        "Engineer" => permission != Permission.ManageUser,
        "Operator" => permission is Permission.View or Permission.Operate,
        _ => false
    };
```

- 密码存哈希（PBKDF2/BCrypt），**绝不存明文**；
- 关键操作写审计日志（谁、何时、改了什么、旧值→新值）；
- 界面按权限隐藏/禁用按钮（但**服务端也要校验**，别只靠界面）。

## 7. 报表

| 报表 | 内容 | 频率 |
|---|---|---|
| 班报 | 班次产量、报警次数、平均值/最大值 | 每班 |
| 日报 | 日产量、合格率、能耗 | 每天 |
| 月报 | 趋势、对比 | 每月 |
| 追溯 | 单件产品的工艺曲线 | 按需 |

实现：

1. 从历史库聚合（SQL `GROUP BY`）；
2. 生成 Excel（`ClosedXML`/`NPOI`/`XlsxWriter`）；
3. 存到指定目录，或发邮件/上传 MES。

## 8. MES 对接

典型接口：

```
POST /api/production/order      获取工单
POST /api/production/result     上报产量/结果
POST /api/equipment/status      上报设备状态
GET  /api/material/check        物料校验
```

工程要点：

- **超时 + 重试 + 幂等**（同一流水号重复提交不重复计数）；
- 断网时本地缓存，恢复后补传；
- 接口失败不能阻塞生产，要降级；
- 记录请求/响应日志（脱敏）。

## 9. 冗余与断线缓存

| 场景 | 方案 |
|---|---|
| 网络抖动 | 重连 + 本地缓存 + 补传 |
| 数据库故障 | 先写本地文件，恢复后导入 |
| 双机热备 | 主备心跳，备机只读 |
| 断电 | UPS + 事务 + 定期备份 |

## 11. 面试怎么讲架构

用 STAR + 一张图：

> S：产线有 12 台设备、3 种协议，原来一个 Form 写到 8000 行，加一台设备要改一周。
> T：重构为分层 + 驱动接口，新设备接入 ≤ 1 天。
> A：抽 `IDeviceDriver`，配置驱动创建；采集/报警/存储拆服务；UI 只订阅事件；加日志和自检。
> R：新设备接入从 5 天降到 0.5 天；连续运行 30 天无崩溃；通信故障定位时间从 2 小时降到 10 分钟。

**有数字、有对比、有你的决策**，比背概念强十倍。
