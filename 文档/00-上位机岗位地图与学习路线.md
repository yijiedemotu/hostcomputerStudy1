# 00 上位机是什么：岗位地图与 12 周学习路线

> 本章目标：搞清楚“上位机”到底做什么、企业招人看什么、你要在 12 周里练出哪些能力。
> 先看全局，再动手，能少走 80% 的弯路。

---

## 1. 一句话定义

**上位机 = 运行在工控机 / 普通 PC 上，与现场设备（PLC、仪表、板卡、机器人、相机）通信，负责人机交互、数据采集、报警、存储和报表的软件。**

“上位机”是相对“下位机”说的：

| 角色 | 典型硬件 | 跑什么 | 职责 |
|---|---|---|---|
| 下位机 | PLC、运动控制卡、单片机、智能仪表 | 梯形图 / ST / C | 实时控制、逻辑联锁、驱动执行机构 |
| 上位机 | 工控机、触摸屏一体机、服务器 | C# / C++ / Python | 监控、参数下发、数据记录、报警、对接 MES |
| 云端/MES | 服务器 | Java / C# / Go | 生产管理、追溯、报表、排产 |

一句话记住：**下位机保证“设备能动、安全停”，上位机保证“人看得见、数据留得下、系统连得上”。**

---

## 2. 上位机工程师每天都在干什么

按时间占比，一个典型项目大致是这样：

1. **看手册、对地址（25%）**：PLC 的 DB 块偏移、仪表的寄存器表、字节序、量程。
2. **写通信与采集（30%）**：串口 / TCP、Modbus / S7 / OPC UA、断线重连、批量读优化。
3. **写界面（25%）**：主界面、参数页、曲线、报警、权限、配方。
4. **数据与报表（10%）**：历史库、班报日报、导出 Excel、对接 MES。
5. **现场调试与救火（10%）**：干扰、IP 冲突、驱动没装、客户改需求。

所以这个岗位**不是纯写界面的**，也不是纯后端的。它是“协议 + 桌面软件 + 现场工程”的混合体。

## 3. 岗位名称与技能要求

招聘网站上你会看到这些名字，本质是同一类工作：

- 上位机软件工程师 / 上位机开发工程师
- 自动化软件工程师 / 电气软件工程师
- C# 上位机开发（最常见）
- SCADA 工程师 / 组态工程师（偏组态王、WinCC、Ignition）
- 视觉软件工程师（上位机 + Halcon/OpenCV）
- MES / 数据采集工程师（偏接口与数据库）

| 层级 | 技能 | 要求程度 | 本教程对应章节 |

### 3.2 拆一段真实 JD

> 岗位职责：负责非标设备上位机软件设计开发；与 PLC 工程师配合完成设备联调；负责数据采集、报表、MES 接口；编写技术文档。
> 任职要求：本科，3 年以上 C# 开发经验；熟悉 WinForms/WPF、多线程、Socket、串口；熟悉 Modbus、OPC、S7 协议；熟悉 SQL Server/MySQL；能适应出差。

翻译成学习任务：

| JD 关键词 | 你要练的东西 |
|---|---|
| 非标设备上位机 | 一个完整项目：配置 + 采集 + 界面 + 报警 + 存储 |
| 与 PLC 联调 | Modbus 报文、地址对照、字节序、调试五步法 |
| 数据采集/报表 | 时序表设计、批量写、按班次统计、Excel 导出 |
| MES 接口 | HTTP + JSON、接口幂等、断线重传 |
| 多线程/Socket | 采集线程、UI 线程、重连、取消 |
| 能适应出差 | 现场排查手册、沟通与验收 |

## 4. 薪资与职业路径（只作参考）

> 薪资受城市、行业、是否出差、公司规模影响极大，以下只是“量级感”，不是承诺。

| 阶段 | 经验 | 典型月薪（一线/新一线） | 能力标志 |
|---|---|---|---|
| 入门 | 0~1 年 | 6~10k | 能照着模板改界面、调通 Modbus |
| 独立 | 1~3 年 | 10~18k | 独立负责一台设备/一条线的上位机 |
| 熟练 | 3~5 年 | 15~25k | 架构、多设备、MES 对接、带新人 |
| 资深 | 5 年+ | 25~40k+ | 产线级 SCADA、团队/项目管理 |

职业路径：

```
上位机开发 → 自动化软件主管 → SCADA/MES 架构 → 项目经理 / 技术专家
                 ↘ 视觉软件（Halcon/OpenCV）
                 ↘ 嵌入式/运动控制（C++/Qt）
                 ↘ 产品/售前（懂现场又懂软件）
```

**这个行业的天花板不在语言，而在“你懂不懂工艺”。** 懂注塑工艺、懂锂电叠片、懂包装线的上位机，工资能比只会写界面的高 50%。

## 6. 学习原则（很重要）

1. **项目驱动**：每学一个知识点，立刻塞进项目里。只看不写，两周就忘。
2. **先跑通，再深挖**：先让数据在界面上跳起来，再去研究 MBAP 头为什么是 7 字节。
3. **每章有产出**：本教程每章末尾都有“验收任务”，做完再进下一章。
4. **读官方文档**：微软 docs、Modbus 规范、PLC 手册。中文博客只能救急，不能当依据。
5. **学会看报文**：串口助手 + Wireshark 是你的听诊器。**能看懂 16 进制，就超过一半新手。**
6. **记录问题**：建一个 `踩坑.md`，写“现象 → 原因 → 解决”。面试时这就是你的素材库。

## 7. 新手最常见的 7 个误区

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 只学语法，不做项目 | 面试一问项目就露馅 | 本仓库三个项目至少做完两个 |
| 追求炫酷界面，不懂协议 | 现场调不通，立刻被看穿 | 先把 Modbus 报文手算对 |
| 不写日志、不处理异常 | 现场出错无法定位 | 第 12 章日志规范照做 |
| 采集直接写在按钮事件里 | 界面卡死、无法停止 | 采集放后台 Task，UI 只订阅 |
| 地址照抄，不看手册 | 读出来全是 0 或异常码 02 | 学会 0/1 基址、字序、量程 |
| 不用 Git | 改崩了回不去 | 第 03 章 Git 基础 |
| 只背面试题 | 一问“为什么”就卡住 | 用项目讲原理，用原理解释项目 |
