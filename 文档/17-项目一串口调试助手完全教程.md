## 1. 5 分钟跑通（推荐：免驱动路线）

### 1.1 启动虚拟串口对服务

```powershell
cd D:\上位机\上位机学习大全

# 终端 1：保持运行
dotnet run --project com0com虚拟串口工具/VComPair
```

在窗口点 **「① 启动服务」**，确认显示 `● 服务运行中 · 127.0.0.1:9527`、
`VCOM2：已连接 · 内置终端`、`VCOM1：空闲`。

### 1.2 启动串口助手

```powershell
# 终端 2
dotnet run --project 项目/src/SerialAssistant
```

### 1.3 打开端口并互发

1. 端口下拉框选 **VCOM1**（列表末尾固定追加 VCOM1 / VCOM2）；
2. 点「打开串口」→ 按钮变「关闭串口」，状态栏变绿；
3. 切回 VComPair，在 VCOM2 面板输入 `Hello COM!` 点「发送」→ 串口助手接收区出现 `[时间] Hello COM!`；
4. 在串口助手发送框（默认 `01 03 00 00 00 0A C5 CD`，已勾 HEX 发送）点「发送 (Ctrl+Enter)」→ VComPair 的 VCOM2 面板与右侧监控窗口都显示这一帧。

> 详细步骤、自动应答、回环模式、换端口见
> [`../com0com虚拟串口工具/06-VComPair免驱动工具完全教程.md`](../com0com虚拟串口工具/06-VComPair免驱动工具完全教程.md)。

### 1.4 换成真实串口 / com0com

同一份代码，把这些名字填进端口框即可：

| 端口来源 | 填什么 | 备注 |
|---|---|---|
| USB 转 RS485 | `COM3` 等 | 设备管理器里查；CH340/CP2102/FT232 驱动要装好 |
| com0com | `COM5` / `COM6` | 一对端口分给两个程序，见 [03 号教程](../com0com虚拟串口工具/03-创建串口对与命令行详解.md) |
| VComPair | `VCOM1` / `VCOM2` | 需要先启动服务 |

**代码会自动分流**：`COMx` → Win32 实现；`VCOMx` → TCP 回环实现。业务代码完全不感知。

```
├───────────────────────────────────────────────────────────────┤
│ ④ 发送区（多行输入框，SplitContainer 下半）                      │

│ ⑤ 状态栏：未打开 | 收 0 字节 | 发 0 字节 | 提示文字                │

```

| 区 | 控件 | 作用与注意点 |
|---|---|---|
| ① | 串口 / 刷新 | 下拉框是 `DropDown` 可手输；点「刷新」重读注册表 `HARDWARE\DEVICEMAP\SERIALCOMM` 并追加 VCOM 项 |
| ① | 波特率 / 数据位 / 校验 / 停止位 | 打开期间**禁用**，防止界面参数和实际端口不一致 |
| ① | 打开串口 | 已打开时变成「关闭串口」，同一个按钮处理开/关 |
| ② | HEX 显示 | 每字节显示两位十六进制；"一帧"= 一次 Read 的块，不等于协议帧 |
| ② | 时间戳 / 自动滚动 / 暂停显示 | 排查帧间隔、长时间跑数时防止刷屏 |
| ② | 编码 | UTF-8 / GB2312 / ASCII，国产仪表常用 GB2312 |
| ② | 清空接收 / 保存日志 | 保存为 UTF-8 带 BOM 的 txt |
| ④ | HEX 发送 | 解析 `01 03`、`0103`、`0x01,0x03` 等写法；字符数必须偶数 |
| ④ | 追加 `\r\n` | 很多仪表以回车换行结束命令 |
| ④ | 定时发送 / 间隔 | `System.Windows.Forms.Timer`，50ms ~ 600000ms |
| ④ | 发送 (Ctrl+Enter) | 快捷键 `Ctrl+Enter`，`SuppressKeyPress` 阻止输入框换行 |
| ⑤ | 收/发字节数 | `long + Interlocked`，因为接收线程和 UI 线程都会改 |

## 4. 核心代码逐段讲解

### 4.1 为什么先抽 `ISerialPort`

`项目/src/Industrial.Core/Transport/ISerialPort.cs`：

```csharp
public interface ISerialPort : IDisposable
{
    bool IsOpen { get; }
    string PortName { get; }
    void Open();
    void Close();
    void Write(byte[] data);
    int Read(byte[] buffer, int offset, int count, int timeoutMs);
    void DiscardBuffers();
}
```

三个价值（面试常问）：

1. **业务代码不依赖具体实现** —— 换 Win32、换 `System.IO.Ports`、换厂商 DLL、换虚拟口，都只换一个类；
2. **可测试** —— 单元测试塞一个内存回环实现，不需要硬件；
3. **语义统一** —— `Read` 约定"超时返回 0 而不是抛异常"，所有实现都必须遵守。

本仓库有两个实现：

| 实现 | 底层 | 打开方式 |
|---|---|---|
| `SerialPortNative` | Win32 API | `CreateFile("\\\\.\\COM3")` → `GetCommState/SetCommState` → `SetCommTimeouts` → `ReadFile/WriteFile` |
| `VirtualSerialPort` | TCP 回环 | 连 `127.0.0.1:9527` → 发 `HELLO|VCOM1|SerialAssistant` → 收 `+OK` → 之后裸字节透传 |

### 4.2 端口分流（本次新增的关键两行）

`MainForm.cs`：

```csharp
private ISerialPort? _port;   // 字段类型从 SerialPortNative 改成接口

ISerialPort port = VirtualSerialPort.IsVirtualPort(settings.PortName)
    ? new VirtualSerialPort(settings.PortName.Trim().ToUpperInvariant())
    : new SerialPortNative(settings);
```

`RefreshPortList()` 里把物理口和 `VirtualPortNames` 一起塞进下拉框，并在没有物理口时默认给 `VCOM1`，

```csharp
var physical = SerialPortNative.GetPortNames();
var ports = new string[physical.Length + VirtualSerialPort.VirtualPortNames.Length];
Array.Copy(physical, ports, physical.Length);
Array.Copy(VirtualSerialPort.VirtualPortNames, 0, ports, physical.Length, ...);
```

**结果**：接收循环、HEX 解析、定时发送、日志保存这些代码一行没改。这就是"面向接口编程"的收益。

### 4.3 打开失败要翻译成中文

`SerialPortNative.DescribeError()` 把 Win32 错误码翻译成现场能看懂的话：

| 错误码 | 提示 |
|---|---|
| 2 / 3 | 端口不存在，检查 USB 转串口是否插好、驱动是否安装 |
| 5 | 端口被占用（通常是另一个调试软件还开着） |
| 31 | 设备未连接或驱动异常 |
| 87 | 参数不合法（波特率/数据位写错） |
| 1167 | 设备无法识别，换 USB 口或换线 |

`VirtualSerialPort` 同理：连不上服务时提示"请先启动『虚拟串口对工具 VComPair』"，端口被占用时提示"同一串口只能被一个程序打开"。

> 现场排障的第一课：**错误信息要能指导下一步动作**，不要只抛 `Win32 5`。

### 4.4 后台接收循环 + 跨线程 UI

`MainForm.StartReceiveLoop()`：

```csharp
_receiveTask = Task.Run(() =>
{
    var buffer = new byte[8192];
    while (!_closing && _port is not null)
    {
        var n = port.Read(buffer, 0, buffer.Length, 50);  // 阻塞读，最多 50ms
        if (n <= 0) continue;
        var chunk = new byte[n];
        Buffer.BlockCopy(buffer, 0, chunk, 0, n);
        Interlocked.Add(ref _rxBytes, n);
        if (_closing || IsDisposed) break;
        BeginInvoke(new Action<byte[]>(AppendReceived), chunk);  // 切回 UI 线程
    }
});
```

四个要点：

1. **不能在 UI 线程做阻塞读** —— 否则窗口假死；
2. **`BeginInvoke` 而不是 `Invoke`** —— 异步排队，不阻塞接收线程；
3. **必须复制出 `chunk`** —— `buffer` 下一轮会被覆盖，直接传引用会读到错数据；
4. **捕获 `ObjectDisposedException` / `InvalidOperationException` / `IOException`** —— 关串口时读线程会抛这些，属于正常退出。

`AppendReceived()` 一定在 UI 线程执行，才能直接改 `RichTextBox`。它还做了两件事：
把裸 `\r` 补成 `\r\n`（否则 RichTextBox 显示异常换行），以及**超过 40 万字符就删掉前 20 万**（防止长时间跑数卡死）。

### 4.5 HEX 解析

`MainForm.ParseHex()`（`internal static`，可单测）：

```csharp
// 允许空格、逗号、0x 前缀；过滤后剩下的字符必须全是 HEX 且个数为偶数
"01 03 00 00 00 0A"  → 6 字节
"01030000000A"        → 6 字节
"0x01,0x03"           → 2 字节
"01 03 0"             → FormatException：HEX 字符个数必须是偶数
"01 GG"               → FormatException：非法字符 'G'
```

实现思路：逐字符过滤分隔符 → 跳过 `0x` → `Uri.IsHexDigit` 校验 → 每两字符 `Convert.ToByte(s, 16)`。

### 4.6 关闭顺序（很容易写错）

`ClosePort()`：

```csharp
tmrAutoSend.Stop();                       // ① 先停定时器
if (chkAutoSend.Checked) chkAutoSend.Checked = false;
var port = _port; _port = null;            // ② 先置空，接收循环靠它退出
try { port?.Close(); } catch { ... }       // ③ 关端口
try { _receiveTask?.Wait(500); } catch { }// ④ 等接收线程退出（加超时防死锁）
SetUiOpen(false);                         // ⑤ 最后恢复界面
```

**如果先恢复界面**，用户可能马上又点"打开串口"，而旧端口还没释放 —— 现场最典型的偶发 bug。

### 4.7 编码注册

`Program.cs` 里注册了 CodePages：

```csharp
Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
```

.NET Core 默认不带 GB2312/GBK，不注册会在切换编码时抛异常。国产仪表大量使用 GBK，这一步是必备的。

## 6. 排错表

| 现象 | 检查顺序 |
|---|---|
| 打开 VCOM1 报"连不上虚拟串口服务" | VComPair 是否启动并点了「① 启动服务」→ 端口是否 9527 → 防火墙是否拦本机回环 |
| 打开 COM3 报"端口不存在" | 设备管理器看 COM 号 → 换 USB 口 → 装 CH340/CP2102/FT232 驱动 |
| 报"端口被占用" | 关掉其他调试助手 / 上位机；VComPair 里点「断开」释放 VCOM1 |
| 能打开但收不到 | 对端是否打开 → 是不是同一对 → 监控窗口有没有流向 → 是否勾了"暂停显示" |
| 中文乱码 | 两端编码一致；国产仪表切 GB2312；确认 `Program.cs` 注册了 CodePages |
| 一个汉字显示成 `?` | UTF-8 汉字 3 字节被拆到两次 Read。生产代码要用 `Decoder` 保存状态或按帧解码 |
| HEX 发送报错 | 字符数是否偶数、有没有混入非法字符 |
| 定时发送关不掉 | 关串口时 `ClosePort()` 会强制停定时器并取消勾选 |
| 长时间运行变卡 | 接收区超 40 万字符会自动截断；也可手动「清空接收」 |
| 关闭窗口时报错 | 接收线程靠 `_closing` 退出，异常被按类型捕获；不要改掉这些 catch |

## 7. 面试怎么讲这个项目

| 问题 | 回答要点 |
|---|---|
| 为什么用后台线程收串口？ | 阻塞读会卡死 UI；`Task.Run` + 带超时的 `Read`，UI 用 `BeginInvoke` 更新 |
| `Invoke` 和 `BeginInvoke` 区别？ | 同步等 UI 处理完 vs 异步排队；高频收数用后者，避免接收线程被拖慢 |
| 怎么处理粘包/半包？ | 串口按"块"返回，不等于协议帧；Modbus RTU 靠 3.5 字符空闲间隔或长度字段切帧 |
| 串口打不开有哪些原因？ | 不存在/被占用/驱动异常/参数非法/COM10+ 缺 `\\.\` 前缀；错误信息要能指导下一步 |
| 没有硬件怎么测？ | 抽象 `ISerialPort`，塞内存回环或虚拟串口实现；本仓库提供 VComPair 免驱动方案 |
| 关闭串口为什么要按顺序？ | 停定时器 → 置空 → 关端口 → 等线程 → 恢复 UI，否则端口未释放就被重复打开 |
| 怎么支持 GBK 仪表？ | `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` + 界面可切编码 |
