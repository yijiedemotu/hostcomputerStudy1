# 07 Modbus 完全指南

> 本章目标：能凭记忆写出 Modbus 报文、独立调通任何一台 Modbus 设备、定位现场 90% 的通信问题。
> 本仓库 `Industrial.Core/Modbus/` 是完整实现，`tools/SelfCheck` 可现场验证。

## 1. 它是什么

Modbus 是 1979 年 Modicon 为 PLC 发明的**主从式应用层协议**，公开、简单、免费，成了工业界的“普通话”。

- **一主多从**：总线上只有一个主站（你的上位机/PLC），从站（仪表、变频器、IO 模块）只能被动应答。
- **从站地址 1~247**，0 是广播（不回应答）。
- **一问一答**：主站发请求，从站在规定时间内回一帧。没有应答就是超时。

三种传输方式：

| 方式 | 物理层 | 帧格式 | 校验 | 使用场景 |
|---|---|---|---|---|
| Modbus RTU | RS485/RS232 | 二进制，紧凑 | CRC16 | 现场 95% 的 485 设备 |
| Modbus TCP | 以太网 | MBAP 头 + PDU | 靠 TCP 校验 | PLC、网关、电表 |
| Modbus ASCII | 串口 | 可读字符 | LRC | 老设备，罕见 |

## 2. 数据模型：四个区

| 区 | 名称 | 读写 | 地址范围（5 位写法） | 协议地址 | 位/字 |
|---|---|---|---|---|---|
| 0x | 线圈 Coils | 读写 | 00001~09999 | 0~9998 | 位 |
| 1x | 离散输入 Discrete Inputs | 只读 | 10001~19999 | 0~9998 | 位 |
| 3x | 输入寄存器 Input Registers | 只读 | 30001~39999 | 0~9998 | 16 位字 |
| 4x | 保持寄存器 Holding Registers | 读写 | 40001~49999 | 0~9998 | 16 位字 |

**最坑的地址换算**：

```
PLC 手册写 40001  →  协议报文里的地址是 0
PLC 手册写 40101  →  协议报文里的地址是 100
```

即：**保持寄存器协议地址 = 手册地址 - 40001**。

但有些国产仪表手册直接给“寄存器地址 0/1”，还有的从 1 开始计数（1 基址）。
**对不上时，先试 0 和 1 两个偏移，再看是否返回异常码 02。**

## 3. 功能码

| 功能码 | 名称 | 作用 | 数量限制 |
|---|---|---|---|
| 0x01 | Read Coils | 读线圈 | ≤2000 位 |
| 0x02 | Read Discrete Inputs | 读离散输入 | ≤2000 位 |
| 0x03 | Read Holding Registers | 读保持寄存器 | ≤125 个 |
| 0x04 | Read Input Registers | 读输入寄存器 | ≤125 个 |
| 0x05 | Write Single Coil | 写单个线圈 | 1 位 |
| 0x06 | Write Single Register | 写单个寄存器 | 1 个 |
| 0x0F | Write Multiple Coils | 写多个线圈 | ≤1968 位 |
| 0x10 | Write Multiple Registers | 写多个寄存器 | ≤123 个 |

实际项目里 **03 / 06 / 10 三个就够用 80%**，01/02 用于读状态和报警位。

### 3.1 异常码

| 码 | 含义 | 常见原因 |
|---|---|---|
| 01 | 非法功能码 | 从站不支持该功能 |
| 02 | 非法数据地址 | 地址越界、基址差 1、数量超限 |
| 03 | 非法数据值 | 写入值超范围 |
| 04 | 从站设备故障 | 从站内部错误 |
| 05 | 确认 | 已接受，处理中 |
| 06 | 从站忙 | 稍后重试 |
| 0A | 网关路径不可用 | 网关配置错 |
| 0B | 网关目标设备无响应 | 站号错、从站掉线 |

异常应答：**功能码最高位置 1**。例如读保持寄存器出错：

```
请求：01 03 00 00 00 01
应答：01 83 02 C0 F1     ← 0x83 = 0x03 | 0x80，异常码 02
```

## 4. RTU 帧格式

```
[从站地址 1B][功能码 1B][数据 N B][CRC 2B，低字节在前]
```

### 4.1 读保持寄存器（03）

读站号 1 的 0~9（10 个寄存器）：

```
请求：01 03 00 00 00 0A C5 CD
      │  │  │     │     └─ CRC（低字节 C5，高字节 CD）
      │  │  │     └─ 数量 10
      │  │  └─ 起始地址 0
      │  └─ 功能码 03
      └─ 站号 1

应答：01 03 14 [20 字节数据] CRC
      │  │  └─ 字节数 0x14 = 20（10 个寄存器 × 2）
      │  └─ 功能码
      └─ 站号
```

读 4 个寄存器的完整例子（值 100、200、300、400）：

```
请求：01 03 00 00 00 04 44 09
应答：01 03 08 00 64 00 C8 01 2C 01 90 90 08
                └100 └200 └300 └400
```

### 4.2 写单个寄存器（06）

把站号 1 的 5 号寄存器写成 888（0x0378）：

```
请求：01 06 00 05 03 78 99 19
应答：01 06 00 05 03 78 99 19    ← 原样回显
```

### 4.3 写多个寄存器（10）

把站号 1 的 0、1 号寄存器写成 100、200：

```
请求：01 10 00 00 00 02 04 00 64 00 C8 B3 E6
      │  │  │     │     │  └─ 数据 100、200
      │  │  │     │     └─ 字节数 4
      │  │  │     └─ 数量 2
      │  │  └─ 起始地址 0
      │  └─ 功能码 10
      └─ 站号

应答：01 10 00 00 00 02 41 C8    ← 回显起始地址和数量
```

### 4.4 分帧规则

RTU 没有帧头，靠**静默时间**分帧：

- 帧内字节间隔 < 1.5 个字符时间；
- 帧与帧之间 ≥ **3.5 个字符时间**。

9600-8-N-1 下 1 个字符 = 10 位 ≈ 1.04 ms，3.5 字符 ≈ 3.6 ms。
本仓库取 `max(2ms, 3.5×字符时间)`，稳一点。

> 调试时如果两帧发得太快，从站可能把两帧粘成一帧 → CRC 错。加 10ms 延时最保险。

## 5. TCP 帧格式

```
[事务号 2B][协议号 2B=0][长度 2B][单元号 1B][功能码 1B][数据 N B]
 └────────────── MBAP 头（7 字节）──────────────┘
```

- **长度** = 单元号 + PDU 的字节数（不含 MBAP 前 6 字节）。
- **事务号** 用于匹配请求与应答，主站自己递增。
- **单元号** 相当于 RTU 的站号；直连设备通常填 1 或 0xFF，经过网关时填从站地址。

读站号 1 的 0~9（10 个寄存器）：

```
请求：00 01 00 00 00 06 01 03 00 00 00 0A
      │     │     │     │  │  │     └─ 数量 10
      │     │     │     │  │  └─ 起始地址 0
      │     │     │     │  └─ 功能码 03
      │     │     │     └─ 单元号 1
      │     │     └─ 长度 6（单元号 + 5 字节 PDU）
      │     └─ 协议号 0
      └─ 事务号 1

应答：00 01 00 00 00 17 01 03 14 [20 字节数据]
      └─ 长度 0x17 = 23 = 1(单元号) + 1(功能码) + 1(字节数) + 20(数据)
```

> TCP 没有 CRC，靠以太网/TCP 校验。**但应用层仍要校验事务号、功能码、字节数**，否则串包会写错数据。

## 6. 数据类型与字序

寄存器是 16 位的，装 32 位/浮点要占 2 个（64 位占 4 个）。解析顺序即第 06 章的 ABCD/CDAB/BADC/DCBA。

```csharp
// 本仓库 RegisterCodec
var raw = RegisterCodec.Decode(registers.AsSpan(0, 2), RegisterDataType.Float32, RegisterOrder.Cdab);
var engineering = RegisterCodec.ToEngineering(raw, scale: 0.1, offset: 0);
```

工程量换算：

```
工程值 = 原始值 × Scale + Offset
原始值 = (工程值 - Offset) / Scale
```

例：温度寄存器 865，Scale 0.1 → 86.5℃；要写入 90.0℃ → 原始值 900。

常见数据类型与范围：

| 类型 | 寄存器数 | 范围 |
|---|---|---|
| UInt16 | 1 | 0 ~ 65535 |
| Int16 | 1 | -32768 ~ 32767 |
| UInt32 | 2 | 0 ~ 4294967295 |
| Int32 | 2 | ±21 亿 |
| Float32 | 2 | ±3.4e38，7 位有效数字 |
| Float64 | 4 | 双精度 |

**注意**：很多仪表用 Int16 表示 -50.0℃，读出来是 65486，要按有符号解析。

## 7. 读取策略：批量读是性能关键

一帧 03 最多读 125 个寄存器。20 个点位如果一个个读，就是 20 帧；合并成 1~2 帧，速度提升 10 倍以上。

本仓库 `PollingService.BuildGroups`：

```csharp
// 地址相邻（间隔 ≤2）的点位合并，上限 125 个寄存器
var canMerge = point.Address <= last.Start + last.Count + 2
            && point.Address + count - last.Start <= 125;
```

代价是可能多读几个空地址，但**多读 2 个寄存器的成本远小于多发一帧**（485 上每帧还有 3.5 字符静默 + 从站处理时间）。

### 7.1 写入策略

- 单个 16 位值 → 06；
- 32 位值/多个连续值 → 10；
- 写之前最好先读回确认（尤其设定值）；
- 写线圈用 05，值 `FF 00` = ON，`00 00` = OFF（不是 01/00！）。

## 8. 超时与重试

| 参数 | 推荐值 | 说明 |
|---|---|---|
| RTU 应答超时 | 300~1000 ms | 9600 下 200ms 通常够，长总线放宽 |
| TCP 应答超时 | 1000~3000 ms | 网络设备可能慢 |
| 重试次数 | 2~3 次 | 连续失败再判定离线 |
| 重连间隔 | 2~5 s | 退避，别狂连 |
| 采集周期 | 200~1000 ms | 太快会拖死 485 总线 |

**连续失败 3 次才报“设备离线”**，避免一次干扰就满屏报警。

## 9. 调试五步法（现场照着做）

```
第 1 步：读手册
  ├─ 确认物理接口（RS485/网口）、波特率、站号
  ├─ 找到寄存器表：地址、数据类型、量程、读写权限
  └─ 确认地址基址（0 还是 1）和字序

第 2 步：串口助手发已知帧
  ├─ 发 01 03 00 00 00 0A C5 CD（读 10 个寄存器）
  ├─ 有回包 → 物理层和参数 OK
  └─ 没回包 → 查线、站号、波特率、A/B

第 3 步：Modbus Poll / 本仓库代码验证
  ├─ 能稳定读 → 进入第 4 步
  └─ 偶发错 → 查终端电阻、干扰、接地、总线负载

第 4 步：写代码
  ├─ 先跑通单点读，再做批量读
  ├─ 打印原始寄存器值（十六进制），别急着换算
  └─ 用已知值验证字序和量程

第 5 步：抓包复盘
  ├─ Wireshark 过滤 tcp.port == 502
  ├─ 对比请求/应答的事务号、功能码、地址
  └─ 把异常帧存下来，写进项目文档
```

## 10. 20 个常见坑

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | 站号错 | 超时/异常 0B | 一对一确认站号 |
| 2 | 波特率不一致 | 乱码/超时 | 对齐参数 |
| 3 | A/B 接反 | 完全没数据 | 对调 A/B |
| 4 | 地址差 1 | 异常 02 或读到邻位 | 试 0/1 基址 |
| 5 | 40001 当协议地址 | 异常 02 | 减 40001 |
| 6 | 字序错 | 数值离谱 | 换 ABCD/CDAB/BADC/DCBA |
| 7 | 量程没乘 | 数值差 10 倍 | 乘 Scale |
| 8 | 有符号当无符号 | 负温变 6 万多 | 用 Int16 |
| 9 | 数量超限 | 异常 03 | 03 一次 ≤125 |
| 10 | 写线圈用 01/00 | 不生效 | 用 FF 00 / 00 00 |
| 11 | 两帧间隔太短 | 偶发 CRC 错 | 加 10ms |
| 12 | 没清接收缓冲 | 把上帧残包当应答 | 发送前清缓冲 |
| 13 | 终端电阻缺失 | 长距离通信不稳 | 两端各加 120Ω |
| 14 | 屏蔽层两端接地 | 干扰大 | 单端接地 |
| 15 | 多主站 | 应答冲突 | 485 上只能一个主站 |
| 16 | 网关单元号填错 | 异常 0B | 单元号=从站地址 |
| 17 | 事务号不校验 | 串包写错数据 | 校验事务号 |
| 18 | TCP 半包 | 偶发解析失败 | 循环读到足够字节 |
| 19 | 超时太短 | 偶发超时 | 放宽到 1s |
| 20 | 采集太快 | 总线拥堵、从站掉线 | 周期 ≥200ms |
