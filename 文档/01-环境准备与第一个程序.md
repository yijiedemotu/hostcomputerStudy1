# 01 环境准备与第一个程序

> 本章目标：把开发环境装好，跑通第一个窗口程序，学会最基本的调试操作。
> 全程命令都能直接复制。**不需要买任何硬件。**

---

## 1. 你需要什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11 64 位 | 上位机几乎只跑 Windows；工控机常见 Win10 LTSC |
| 内存 | 8 GB 起，16 GB 舒服 | 同时开 VS + PLC 软件 + 串口助手很吃内存 |
| 硬盘 | 20 GB 空闲 | SDK + VS 大约 10 GB |
| 显示器 | 1080P 起 | 工业现场常见 1920×1080，界面要按这个调 |
| 硬件 | 无 | 本仓库自带 Modbus 模拟器，纯软件练习 |

软件三件套：

1. **.NET 8 SDK**（LTS，工业项目首选）
2. **Visual Studio 2022 Community**（免费）或 **VS Code + C# 扩展**
3. **Git**（版本管理，求职必备）

> 本仓库用 `net8.0-windows`，这是 2024~2026 年企业存量最大的 LTS 版本。
> .NET 9/10 也能打开，但**新项目建议 8**，因为客户工控机上装的是 8。

## 2. 安装 SDK

### 2.1 用 winget（最快）

```powershell
winget install Microsoft.DotNet.SDK.8
winget install Git.Git
```

### 2.2 手动安装

下载地址：<https://dotnet.microsoft.com/download/dotnet/8.0>
选 **SDK x64**（不是 Runtime，也不是 ASP.NET Core Runtime）。

安装完新开一个 PowerShell 验证：

```powershell
dotnet --version
dotnet --list-sdks
dotnet --list-runtimes
```

正常输出类似：

```
8.0.4xx [C:\Program Files\dotnet\sdk]
Microsoft.NETCore.App 8.0.x
Microsoft.WindowsDesktop.App 8.0.x   ← 有这一行才能跑 WinForms/WPF
```

### 2.3 装 Visual Studio（推荐新手）

下载 VS 2022 Community，安装时勾选工作负载：

- ✅ **.NET 桌面开发**（WinForms + WPF 都在这）
- ✅ 可选：Git、NuGet 包管理器

装完打开 VS，能新建“Windows 窗体应用(.NET)”就说明成功。

## 3. 第一个程序：3 分钟

### 3.1 命令行创建

```powershell
mkdir D:\demo
cd D:\demo
dotnet new winforms -n HelloWinForms
cd HelloWinForms
dotnet run
```

几秒后弹出一个空白窗口。**恭喜，你已经是一个（入门级）上位机开发者了。**

### 3.2 加一个按钮

打开 `Form1.cs`，在设计器里拖一个 `Button`，双击它，VS 自动生成事件方法：

```csharp
private void button1_Click(object sender, EventArgs e)
{
    button1.Text = $"点我 {DateTime.Now:HH:mm:ss}";
    MessageBox.Show("Hello 上位机！");
}
```

按 **F5** 运行，点击按钮看看效果。

### 3.3 背后发生了什么

```
Program.cs           → Application.Run(new Form1())   启动消息循环
Form1.cs             → 你的界面逻辑（事件处理器）
Form1.Designer.cs    → 设计器生成的控件创建代码
*.csproj             → 项目配置（目标框架、是否 WinForms）
```

`Program.cs` 长这样：

```csharp
[STAThread]                     // 单线程单元，WinForms 必须
static void Main()
{
    ApplicationConfiguration.Initialize();
    Application.Run(new Form1());   // 阻塞在这里，直到窗口关闭
}
```

**`Application.Run` 就是 UI 消息循环。** 它所在线程叫 UI 线程，所有控件操作都必须在这个线程上（第 10 章会讲跨线程）。

## 4. 认识 .csproj

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>              <!-- 窗口程序，不弹控制台 -->
    <TargetFramework>net8.0-windows</TargetFramework>
    <Nullable>enable</Nullable>                   <!-- 可空引用类型，强烈建议开 -->
    <UseWindowsForms>true</UseWindowsForms>
    <ImplicitUsings>enable</ImplicitUsings>       <!-- 自动 using，少写几行 -->
  </PropertyGroup>
</Project>
```

常改的几项：

| 配置 | 作用 |
|---|---|
| `TargetFramework` | 目标框架，改成 `net8.0-windows` 就别乱升 |
| `UseWPF` / `UseWindowsForms` | 决定用哪套 UI |
| `ApplicationHighDpiMode` | 高 DPI 适配，工控机缩放 125% 时必须 |
| `AssemblyVersion` / `FileVersion` | 版本号，升级和日志排查要用 |
| `Nullable` | 空引用检查，建议一直开 |

## 5. 调试：比写代码更重要的技能

### 5.1 常用快捷键

| 快捷键 | 功能 | 使用场景 |
|---|---|---|
| F5 | 启动调试 | 正常运行 |
| Ctrl+F5 | 不调试启动 | 快，但没断点 |
| F9 | 打断点 | 让程序停在你怀疑的那一行 |
| F10 | 逐过程 | 一行一行走，不进入方法 |
| F11 | 逐语句 | 进入方法内部 |
| Shift+F11 | 跳出当前方法 | 看够了就跳出来 |
| Ctrl+Shift+F9 | 删除所有断点 | 调试完清理 |
| Ctrl+Alt+W | 监视窗口 | 看变量值 |

### 5.2 断点进阶

- **条件断点**：右键断点 → 条件 → `value > 100`，只在异常值时停。
- **命中次数**：`count % 10 == 0`，每 10 次停一次，专治偶发问题。
- **操作**：命中时打印日志（`$"temp={temp}"`），不中断，适合采集线程。
- **异常设置**：`Ctrl+Alt+E` 勾选 `Common Language Runtime Exceptions`，异常抛出瞬间就断，不用等崩溃。

### 5.3 看什么

1. **调用堆栈**：谁调用了这个方法（现场 bug 必看）。
2. **局部变量**：参数、临时值对不对。
3. **并行堆栈**：多线程项目看各线程在干什么。
4. **输出窗口**：`Debug.WriteLine` 的内容。
5. **诊断工具**：CPU、内存曲线，查卡顿和泄漏。

```csharp
System.Diagnostics.Debug.WriteLine($"收到 {n} 字节：{Convert.ToHexString(chunk)}");
```

### 5.4 调试上位机的顺序

```
现象 → 先看日志 → 再看通讯（报文） → 再看数据（解析） → 最后看界面
```

90% 的“界面不动”其实不是界面的问题，是通信断了或解析错了。

## 6. NuGet：用别人的轮子

NuGet 是 .NET 的包管理器。上位机常用包：

| 包 | 用途 |
|---|---|
| `System.IO.Ports` | 官方串口类（本仓库为了离线，改用 Win32 实现） |
| `Microsoft.Data.Sqlite` | 本地数据库 |
| `NModbus` | Modbus 库（学习阶段建议先手写） |
| `S7netplus` | 西门子 S7 通信 |
| `Serilog` / `NLog` | 日志 |
| `CommunityToolkit.Mvvm` | WPF MVVM 简化 |
| `LiveChartsCore.SkiaSharpView.WinForms` | 图表 |

安装：

```powershell
dotnet add package Microsoft.Data.Sqlite --version 8.0.8
```

> **国内网络提示**：nuget.org 偶尔很慢。可以在 `%AppData%\NuGet\NuGet.Config` 里加镜像。
> 但注意：**面试和现场可能没有网络，核心代码要能只靠 BCL 写出来**——本仓库全部零依赖就是这个原因。

## 7. 本仓库怎么跑

```powershell
cd D:\上位机\上位机学习大全\项目

# 1. 启动 Modbus 从站模拟器（新开一个终端）
```

## 9. 常见环境问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `dotnet` 不是内部命令 | PATH 没生效 | 重开终端；或重装 SDK |
| 提示缺少 `Microsoft.WindowsDesktop.App` | 只装了 Runtime | 装 SDK，或装 Desktop Runtime |
| VS 里新建没有 WinForms 模板 | 没装“.NET 桌面开发” | 打开 VS Installer 补工作负载 |
| `dotnet run` 报 MSB1003 | 不在项目目录 | `cd` 到有 `.csproj` 的目录 |
| 程序一闪而过 | 控制台程序？ | 检查 `OutputType` 是否为 `WinExe` |
| 中文乱码 | 文件编码不是 UTF-8 | VS“另存为 → 带签名的 UTF-8” |
| 路径含中文/空格报错 | 老工具链兼容性 | 换纯英文路径，或升级 SDK |
| 杀毒软件拦截生成 | 误报 | 把项目目录加白名单 |
